# Thor 账号与音频设置内嵌验收

日期：2026-10-31。

## 实现范围

“我的”中的账号、绑定和播放设置入口直接进入 Thor 导航栈。兼容字符串入口也先解析为原生页面，再判断是否需要旧版导航，因此这些路径不再执行 `displayHost.stop()`、解绑播放服务或启动 MainActivity。原来用于返回旧页面的协议保留；“关于”等本轮未迁移的入口仍可使用原兼容机制。

账号页面包括登录方式选择、手机号验证码／密码表单、Web Cookie 表单、嵌入网页登录、账号首页、安全与绑定、登录设备、应用授权及授权历史、关注／粉丝列表。账号歌单进入 Thor 原有详情。复用原来的登录 VM、网易云协议、DataStore 会话和账号业务仓库，没有另存一套账号。听歌统计、排行榜和音乐人页面不在本轮迁移范围，也没有把它们错误映射为授权历史。

音频设置包括播放音质、输出模式、播放与恢复行为、通知按钮、AutoMix，以及真实十段均衡器的开关、预设、前级和频段增益。音质经过原 PlayerConnection，处理设置使用原有 DataStore keys 和 DSP。选项与数值编辑在页面内部完成，B 优先取消未应用的数值。USB 原样输出沿用原能力限制；模拟器不能证明 USB 硬件音质或独占输出表现。

原来的“跳过不可用歌曲”偏好没有被服务消费，本次补上真实行为：关闭时暂停并保留当前条目；开启时沿用原失败预算、自动跳过及队尾保护。在此之前的同曲源刷新和降音质路径保持原行为。

通知中的歌词入口显示为“上屏歌词”，打开 Thor 播放页。媒体、定时与下载通知入口也避免跳回旧 MainActivity。这不表示已把旧版 MainActivity 的 Android PiP 功能迁入 Thor。

## 双屏、手柄与账号边界

- 页面由原 ThorActivity／下屏 Presentation 承载，ViewModel 使用该 Activity 的 owner 和 Hilt factory。三套材质及白天／夜间使用现有主题 Token，二级页面没有一级侧栏。
- 普通账号列表、设置列表、选项和数字编辑各有明确焦点范围；页头和迷你播放器不进入内容光标。Select 长按提供刷新、网页控件和均衡器操作；Start 保持全局播放入口。
- 输入字段先停在独立 wrapper，按 A 或触摸才进入编辑；B 或 IME 完成退出输入并恢复普通方向导航，不自动发送验证码或提交登录。
- Start 覆盖原生表单后返回，手机号、输入、URS 上行挑战与验证码冷却保留在短暂进程内草稿。普通退出表单、切换表单或账号变化时清理；密码、Cookie 不进入 SavedState、路由、日志或持久化。网络任务仍随可见表单取消。
- 手机短信的人机验证继续使用原网易云网页验证协议；单次请求传入下屏 context 和父窗口 token。实际 Dialog factory 使用 attached window，A／B／方向／左摇杆作用于网页，Start 交给 Thor 后取消本次验证。无需为验证再启动旧 Activity。
- 官方网页的 Cookie 和 WebView 初始化显式运行在 Main dispatcher，覆盖 DataStore 异步恢复后不在有 Looper 线程上的复测问题。
- 登录和退出的会话校验在最终 DataStore 编辑内执行。退出、移除设备、撤销授权和设备验证码操作先接受与展示账号匹配的不透明 ticket，再把预期会话指纹传到真实提交位置，拒绝切号后的旧操作。CookieManager 与 DataStore 不构成跨系统原子事务。
- 登录保存与账号投影异步同步后再完成导航；generation 清理与成功回调采用幂等处理，保留原调用列表／账号页，同时清除旧账号详情、网页上下文及管理菜单。

仅使用专用双屏模拟器 `thor_agent_dual_api36`，ADB 目标 `emulator-5560`。测试未操作真机。

| 新增真实窗口与字段测试 | 6 项通过 |
| 既有手柄、焦点、菜单、输入与主题仪器回归 | 32 项通过 |

模拟器上屏为逻辑 display 0（1920 × 1080），下屏为逻辑 display 4（1240 × 1080），密度均为 369。窗口级测试启动真实 Hilt ThorActivity，并以 Activity instance、taskId、上下屏 window token、DecorView 和 Compose host identity 为基线，监控 MainActivity 创建及 Activity 暂停、停止、销毁。

新增 6 项实际验证：

1. 我的 → 音频 → 均衡器 → Start 播放页 → Start 返回 → B 逐级返回，两屏原窗口保留，没有 Activity 暂停／停止／销毁。
2. 我的 → 登录选择 → 手机／Cookie 表单 → Web 登录 → 官方绑定网页的创建和返回，不启动旧 MainActivity，二级页没有根侧栏。
3. 使用生产验证码 factory 和禁止网络的合成网页，确认 Dialog 与 WebView 位于原下屏；A 真实激活网页按钮一次，B 只关闭该窗口。
4. 验证码 Dialog 中 Start 经真实 Activity 手柄路由进入播放器，离开回调一次，原两屏窗口保留，之后返回原手机号页。
5. 真实字段 wrapper 初始不编辑，A 才进入，生产 B 处理退出后可向下导航，并覆盖首帧前快速取消。
6. IME 完成不提交表单；触摸进入和移除字段正确释放编辑 owner。

另外 32 项覆盖线性扳机／肩键适配、IME 按键归属、虚拟长列表和页面菜单的受限焦点、菜单长按、六套材质明暗组合下的控件边界及减少动态。原始构建和测试日志放在忽略目录 `app/build/thor-qa/embedded-pages-*.log`；真实账号页面截图不入库。

最后的 Web 主线程修复后重新执行新增 6 项，并额外单独复测账号／Web 入口 1 项通过；32 项原组件回归此前已通过，未涉及该次修改的 Web 文件。

本轮没有提交新的登录凭据、发送验证码、退出账号、移除真实设备或撤销真实授权。原有登录态保留。验证码窗口测试证明承载和输入路由，不能代替网易云服务器真实挑战的成功验收；第三方账号绑定的官网交互也仍由其服务提供。
