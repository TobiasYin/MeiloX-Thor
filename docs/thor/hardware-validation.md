## 账号迁移与真实服务器验证

- 将 Mobile 账号所需的最小 **8 个字段**迁入目标真机，没有复制源设备指纹；模拟器保留原有登录。
- 迁移后先复现了缺少设备身份（`missingIdentity`）导致 OkHttp 请求路径崩溃的问题；缺失身份初始化已修复，并复用现有 bootstrap 流程。
- 目标设备使用本机身份完成服务器注册，响应业务 `code` 为 **200**。
- 真机通过现有 `MeloXRepository.accountProfile()` 无参路径请求真实服务器 profile，使用布尔断言确认服务器返回的账号与本地保留账号一致，同时检查请求前后账号类型和 ID 未变。该结果依据服务器请求与测试断言。
- 账号验证仪器测试仅在显式传入 `thor.physicalAccount=true` 时执行；未传入时跳过。验证没有执行远程收藏、加入歌曲、创建歌单或其他音乐库写入。

凭据、账号 ID／昵称、迁移中间数据及敏感账号截图不纳入仓库。

## 麦克风权限与录音就绪

- 在真机拒绝麦克风权限后，吹气功能保持关闭，界面可见错误提示。
- 再次允许权限后，界面显示“已就绪”，系统 appops 确认录音处于 running 状态。

权限路径和录音就绪已确认。另修复了重新授权成功后旧失败提示残留的问题；成功启停会显示正确状态并自动消失。

后续用户反馈吹气没有反应，本轮已修复两条确定的代码路径：取消启用时自动将最初 1.5 秒当作安静样本，避免把第一次吹气存成噪声；拖动期间仍保存最新气流请求，松手后持续相同强度也会恢复气流旋转。校准改为明确的安静、轻吹、强吹三步，只在有效样本完成后进入下一步，失败保留旧配置并允许重试。设置页新增实时强度条。

新包覆盖安装后已重新开启吹气，`appops` 确认运行中，采样使用 UNPROCESSED（source 9）及内置麦克风（route 15），减少动态关闭。Debug 仅记录 RMS、门限、强度等数值，不保存原始音频。等待人工样本期间仍是低于门限的安静信号；没有把采集就绪记作实际吹气通过。实际力度、转速与停吹归正仍待用户反馈。

## 本轮手柄与入口修正

- 用户实体反馈 L2/R2 单次行程切换多首；现将轴与数字键共用锁存，触发后要求轴值回到 ≤0.05 且数字 UP 后才解锁。Android 适配器回归覆盖两种事件先后、部分回弹和完全归零，实物再次按压的结果待确认。
- 播放页 L1/R1 短按分别后退／快进 15 秒，320ms 后进入持续预览，每 50ms 调整 500ms，松开提交；取消、换曲及生命周期中断不提交旧预览。真实主 Looper 的长按和释放已通过仪器测试。
- 在真机暂停曲目上，以 Android 按键注入检查真实播放连接：从 0:04 连续两次 R1 到 0:34，再一次 L1 到 0:19。该结果不代替实体肩键手按验收。
- Start 优先进入播放页，包括菜单及文本编辑态；未提交的命名草稿可在返回后恢复。L3 随机播放、R3 播放全部，只在具有相应批量按钮的歌曲集合或详情页生效。
- 首页、发现底部的常驻本地音乐按钮已移除；本地音乐入口保留在音乐库。真机首页已检查。

## 锁屏、后台与恢复

实际 Android 13 检查中，麦克风在锁屏及切回桌面后停止采集，唤醒及回到应用后按已启用的偏好恢复。锁屏前暂停的 QA 曲目，唤醒后仍暂停且队列为 3；播放后切桌面约 2 秒，返回时同一曲目进度为 0:03，继续播放，随后手动暂停。上下屏正常恢复。

上一轮系统夜间 yes/no 实际切换后，上下屏均跟随变化，两块窗口 ID 保持不变；结束恢复原系统夜间 yes，关闭吹气并确认录音停止、暂停 QA 音频。本轮为人工重试重新开启吹气，当前偏好保持开启，后台／锁屏仍按生命周期停止采集。

上一轮配合窗口没有收到手柄或合盖事件，随后用户补充了实体扳机重复及吹气无反应的反馈，本轮据此修正。修正后的实体按键、真正吹气和合盖仍不记为通过。Android 按键注入、适配器回归、权限、锁屏与后台检查分别记录，不能互相替代。
