## 实测发现与修复

### 搜索接口与结果结构

旧 `/api/search/get/` 在同一真机会话下返回 HTTP 200、业务码 405。五种协议的只读对照中，旧接口的四种组合都报告操作频繁；`interfacepc` 的 EAPI `/api/cloudsearch/pc` 返回正常结果。

普通歌曲、专辑和歌单搜索已改为这个实际可用的云搜索主路径，携带 `total=true`；电台 type 1009 保留原有接口及局部 PC Cookie 契约。没有增加换身份、匿名重试或自动 fallback。现代返回中的 `al/ar/dt/mv/st` 与旧字段共同映射，封面优先使用真实 `picUrl` 和精确图片 ID，缺图不生成 `0.jpg`；内嵌与独立权限仍按歌曲 ID 合并。

最终目录检查核对 160 个搜索结果和 167 份歌曲详情，并实际加载专辑与公开歌单。搜索可能排除原始受限录音、返回翻唱，因此追加了一批有界公共历史 ID 作为发现种子；可播或不可播仍由当前账号的实时详情及后续完整音源验证决定，没有固定假定某个 ID 无版权。

### 云歌单批量加入顺序

真实服务将 `[A,B]` 批量加入空歌单后返回 `[B,A]`，连续六次 fresh 读回都确认成员相同、顺序相反。现已统一为保留原成员顺序、按输入顺序去重追加新成员。

写入后先读取完整成员和原成员相对序列；仅在没有外部变化时复用现有条件排序接口。外部新增、删除、重复成员或原成员重排会拒绝覆盖；部分失败的 Undo 同样受快照保护，不强行回滚其他客户端修改。

最终真实云流程不仅检查空单添加，也在已有 `[A,B]` 后提交 `[C,A,C]`，严格读回 `[A,B,C]`，Undo 后严格读回 `[A,B]`。喜欢、专辑收藏、重复添加、移除及撤销、改名及撤销、删除也分别从服务器回读确认。

## 重跑方式

构建 app 与 AndroidTest 后，只在明确选择目标设备并保留数据安装的前提下执行 allowlist。不要用整个 connectedAndroidTest 自动扫描旧的清队列、缓存或网页登录 fixture。

```sh
adb -s TARGET shell am instrument -w -r \
  -e thor.live true -e thor.physical true \
  -e class com.ljyh.mei.thor.data.ThorLiveCatalogInstrumentedTest \
  com.neoruaa.meilox.test/androidx.test.runner.AndroidJUnitRunner
```

先生成当前设备的 fresh passing catalog，再分别运行 LiveUi、LivePlayback、LiveManagement。Playback 另需 `thor.livePlayback=true`，三个旧故障 wrapper 分别需 `issue59Recovery`、`issue38Recovery`、`issue57Recovery=true`；真实云修改另需 `thor.liveMutations=true`。这些开关缺失时普通 CI 可跳过，明确启用后的网络、登录、候选或功能失败必须失败。不要把交互式 `thor.liveManual` 加入无人值守批量。
