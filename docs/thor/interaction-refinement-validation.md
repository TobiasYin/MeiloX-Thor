# 列表播放、搜索、提示与上屏焦点修正

日期：2026-10-31。源码提交 `e87ed087`。全部设备验证使用双屏专用模拟器 `thor_agent_dual_api36`，ADB `emulator-5560 / server 5038`；上屏 display 0、1920×1080，下屏 Presentation display 4、1240×1080。未操作真机，没有登录、喜欢、收藏或歌单的云端写入。

## 交付行为

| 场景 | 修正后的行为 |
|---|---|
| 歌曲列表 A／触摸选歌 | 播放桥接受请求后立即进入播放器。空列表、断连失败仍留在原页并提示，不假装播放成功 |
| 播放页 B／Start 返回 | 返回原来的来源页，保留选中项、首个可见条目的稳定 key 及像素偏移，不重新进入首项 |
| 队列选歌 | 统一进入单个播放器层，保留原浏览返回历史，不重复堆叠 Player |
| 可见搜索按钮／IME Search／手柄 A | 读取当时可见的关键词，通过同一个提交回调搜索；正在加载时显示“搜索中”，空白或重复加载不提交 |
| 搜索编辑时 B | 关闭编辑并保留关键词；再次 B 才按原导航返回 |
| 普通成功提示 | 3.5 秒后自动消失 |
| 带“撤销”的成功提示 | 保留 6 秒操作时间，然后自动消失；重复同文重新计时，旧定时器不能清除新提示 |
| 搜索编辑期间的提示 | 暂时隐藏 banner，计时继续，避免键盘压缩下屏后撤销／关闭按钮盖住搜索按钮 |
| 上屏封面、歌词标题、歌词及滚动容器 | 不参与手柄／键盘输入焦点，不显示选中框。封面拖动、辅助访问转面、歌词拖动和点行播放继续可用 |

错误提示保留原有的持续显示规则。歌词当前播放行的强调和 `selected` 辅助语义仍表示播放状态，与导航焦点分开。

## 关键实现

`ThorShellViewModel.play()` 在播放请求被接受后调用既有 `showPlayer()`，继续复用 QuickPlayerHistory 保存来源导航。队列页统一调用 `selectQueueEntry()`。列表 Binder 在激活动作前同步保存选中项和视口，不依赖下一帧或销毁回调补写。

原生验证进一步复现了部分露出的首行被系统 BringIntoView 自动滚正的问题：第 20 行、13px 偏移，返回后曾变为 0px。现在仅在恢复已有合法视口、且目标仍可见时，以短暂的高优先级滚动事务保护焦点／布局交付；普通方向导航仍使用正常滚动路径，新的方向请求可以取消旧恢复任务。没有采用先跳到 0 再纠偏的方式。

搜索输入条使用同步 TextFieldValue 缓冲，先捕获可见文本，再结束输入法 composition、关闭编辑并显式提交关键词。VM 在编辑变化时取消旧请求，结果回写同时检查请求与账号 generation，避免旧响应覆盖新输入。真实 ThorInputRouter 的编辑模式仍将 gamepad A/B 交给应用；Lower dispatcher 与输入条共用编辑命令处理。

提示原先只对“不带撤销的成功消息”自动关闭，导致喜欢等带撤销消息常驻。当前每条提示都有独立 ID，计时到期后通过 VM 的按 ID 清除操作再次核验。提示动作也校验 ID，避免已过期的旧动作影响新提示。搜索按钮没有被认定为简单漏接 onClick；同时修复了同步提交、请求竞态和实际可复现的提示热区遮挡。

上屏移除了 CD 的 FocusRequester、focusable、键盘转面处理和自绘焦点框，并禁止标题、歌词行、滚动容器获得输入焦点。Android 默认焦点高亮仅在上屏组合存续期间关闭，退出后恢复；没有将整个 Activity 设置成不可聚焦，也没有移除辅助访问树，因此下屏与单屏回退的输入能力保留。

## 验证结果

Debug APK、AndroidTest APK 构建成功。相关 JVM 回归 **534 项全部通过**，过滤范围沿用 `com.ljyh.mei.thor.*`、`com.ljyh.mei.playback.*`、`*ReadableLyrics*Test`、`*LyricManualScrollStateTest` 和 `*NeteaseLoginSessionGuardTest`。

最终原生验证分两组执行，共 **54 个不同用例全部通过**：

- 新增交互 10 项，38.410 秒：[原始日志](interaction-refinement-evidence/new-interactions.txt)。包括真实列表 Binder／SaveableStateHolder 的 3 项返回测试、真实下屏 Presentation 的 3 项搜索／提示测试，以及真实上屏的 4 项焦点与触摸测试。
- 既有相关回归 44 项，154.241 秒：[原始日志](interaction-refinement-evidence/existing-regressions.txt)。包含焦点边界 9、原生手柄适配 7、播放封面动效 5、PCM→Detector→Canvas 2、外观设置 1、播放背景 3、歌词 12、主题动效 1、视觉契约 4。

新增测试重点覆盖：

1. 手柄／触摸选歌后进入播放层，再返回同一选中项及非零像素偏移；部分露出的第 20 行也精确恢复到 13px。
2. 216dp 紧凑下屏中，先确认旧提示关闭热区确实覆盖搜索按钮中心；编辑后 banner 隐藏，第一次触摸只提交可见关键词，不触发旧提示动作。
3. IME 与真实 Router 收到的 Android gamepad A 使用同一提交路径；B 仅结束编辑并保留草稿。测试不访问真实搜索接口。
4. 普通／撤销提示的时限、重复同文重新计时、旧定时器隔离和错误保留。
5. 封面触摸后尝试焦点动作、方向／确认及 View 级音量键，不产生上屏输入焦点；真实 Dialog 使窗口失焦再恢复，也没有新选中框。
6. 封面拖动、歌词拖动不 seek、点行 seek 一次仍正常，同宿主的独立 BasicTextField 仍可聚焦输入。

上屏失焦测试使用实际窗口往返，不等同于完整复刻系统音量面板。视觉断言保留完整姿态、生命周期、边界与无焦点检查，Canvas 外围 12dp 带逐像素严格相等；内部仅容许最多 32 个、各通道差不超过 32 的 GPU 投影边缘像素。收紧该边界依据是前后 734400 个像素中实际仅 4 个模型边缘像素的栅格化差异，不以整体相似度掩盖新增边框。
