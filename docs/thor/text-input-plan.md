# Thor 纯手柄文字输入实施方案

日期：2026-10-31。**状态：下一轮实施计划，尚未开发，不是当前客户端能力。** 本文具体化 [design.md](design.md) 中P10搜索输入与P16名称编辑已经批准的字符面板；当前原生Search和Name仍依赖系统IME。完成本文不代表实体手柄或全流程登录输入已适配。

## 1. 首个交付切片

搜索和新建/重命名歌单共用一套字符面板，提供：

- 中文：无声调拼音音节输入、候选分页、逐字选入。例如`zhou → 周`、`jie → 杰`、`lun → 伦`，得到“周杰伦”。
- 英文：大小写字母、数字、常用标点与符号；提供删除、空格、清空、光标左右和显式完成动作。
- 手柄：方向键/摇杆选格，A输入或选候选，X删除，Y局部切换输入方式，B逐层退出；触摸可以操作同一组控件。
- 编辑：保留光标及选区，重命名已有文字时可以替换选区；字符插入和删除不拆UTF-16代理对。

首个切片不包含整句拼音引擎、自动分词、模糊拼音、云候选、用户词频学习或独立系统输入法。中文候选覆盖固定字表内有读音的数据；不能承诺所有Unicode汉字均有读音或所有目标设备字体均有对应字形。外部WebView、验证码及第三方登录输入仍按其独立流程验证。

## 2. 固定离线候选数据

仓库当前没有可直接复用的拼音候选字表。首版采用固定的 **Unicode 17.0.0 Unihan** 数据，在开发阶段生成精简资产，应用运行时只做离线查表，不下载字典、不读取系统IME内部词库，也不在设备上枚举汉字临时反建索引。

来源与字段：

- 固定数据归档：[Unicode 17.0.0 UCD目录中的Unihan.zip](https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip)。
- 固定字段说明：[UAX #38，Unicode 17.0.0 / revision39](https://www.unicode.org/reports/tr38/tr38-39.html)。使用`kMandarin`与`kHanyuPinyin`读音，保留多音字；`kHanyuPinlu`中已有的读音频率用于辅助排序。
- 许可：[Unicode License V3](https://www.unicode.org/license.txt)。将所用数据对应的完整版权与许可声明随生成资产保存；按许可保留通知，不只放网页链接。

建议的生成过程：

1. 手动执行离线生成脚本时取得上述固定归档，计算并记录源文件SHA-256。脚本接受本地归档路径，不在正常Gradle构建或应用启动时联网。
2. 解析固定版本中的相关字段，拒绝无效Unicode scalar、格式错误读音及重复候选。读音转为小写、去声调；`ü`及其带调形式规范为`v`，保留与`u`的区别，不能直接删除全部组合标记后把两者合并。
3. 生成`音节 → 有序字符列表`；同一汉字可以出现在多个合法音节下。已知频率按降序，没有频率的候选以基本CJK区优先、再按码点等固定规则排列；同权重结果稳定，不依赖运行设备的Locale。
4. 以UTF-8、固定换行和固定排序输出资产，计算生成文件SHA-256。第二次从同一归档生成应得到相同字节及SHA。
5. 保存manifest：源URL、Unicode版本、字段集、源SHA-256、生成脚本版本、生成文件SHA-256、音节/候选数量及归一化规则。生成后的manifest和许可证与资产一起进入版本控制。

**SHA值在取得归档并生成时填写，本文不编造预期值。** 开发交付必须提供实际值与可重复生成结果。数据版本更新需要显式修改来源与manifest，不能使用`latest`链接静默换表。

运行时首次加载在后台完成，之后使用只读索引；候选查询不访问数据库或账号服务。候选尚未准备好时保持已输入拼音并显示简短加载状态，不阻塞方向键，也不插入错误候选。

## 3. 原生输入所有权

现有`textEditing: Boolean`不能直接承担字符面板模式：SystemIme需要把文字/方向事件交给输入法，CharacterPanel需要由应用接收方向、A/B/X/Y和摇杆。原生路由应明确区分：

| 输入上下文 | 所有者及行为 |
|---|---|
| `Content` | 普通页面方向只当前列表或显式选项 scope；短 Select 松开队列，长 Select 500ms 页面操作，X 条目菜单。Start 保持全局 Player 入口；菜单关闭、seek 取消、Name 草稿挂起。不能以方向进入背景页头/页脚/Tab。 |
| `SystemIme` | 物理文字键、输入法方向/Enter/系统Back交给系统IME；手柄Y、切歌、切Tab及Select长短按不穿透为应用业务，系统媒体播放键保留既有独立来源路由。Start可保留宿主查询词/Name草稿、隐藏IME并进入播放器，返回恢复草稿；第三方IME内部候选状态不作为恢复承诺。 |
| `CharacterPanel` | 唯一活动文字会话拥有方向、摇杆、A/B/X/Y；播放、切歌、Select和L1/R1均不穿透，L1/R1不新增面板用途。Start挂起完整文字会话并进入播放器，返回恢复同账号草稿、选区、组合串、输入方式、候选页与焦点，不自动选字或保存名称；完整面板会话恢复仍属本计划待开发范围。 |

Name 的名称字段、取消/保存与字符面板构成明确编辑区域；方向不进入背景列表或页头/页脚。字符面板拥有独立选项 scope，系统 IME 继续按原生事件归属处理；短/长 Select 都不在文字独占中执行队列或页面操作。

除Start的全局快速播放器入口外，字符面板优先级高于Name菜单、seek和普通导航。当前SystemIme路由阻止Y/L2/R2等手柄业务穿透，保留系统媒体播放键的独立来源路由，并允许Start交给应用；Name草稿挂起由宿主承担。这里记录现有代码边界，验证结果见verification.md；完整CharacterPanel及其会话恢复仍按本计划实施。

Y只在`CharacterPanel`中解释为切输入方式。耳机/系统媒体播放键与物理手柄Y要保留来源区别；媒体键在文字独占期间被消费，不能因为映射到同一个旧命令而改变输入方式。

进入/退出文字会话、会话替换、窗口失焦时清理持有与连发；重新进入内容态后须等待相应按键释放，防止完成键A或关闭键B穿透到搜索结果、父菜单或播放控制。L2/R2在输入期间仍观察归零但不切歌，持有退出文字态后须数字释放且对应轴归零，再次新按才触发。SystemIme与CharacterPanel不能同时开启；打开自有面板时不自动唤起系统软键盘。

## 4. 下屏尺寸与Name共存

以现有逻辑画布为准：Thor约537×468dp，Duo约555×416dp。面板固定在下屏底部，使用本屏实际dp，不按硬件像素写尺寸；所有字符、候选与动作的有效热区至少48dp。

| 面板区域 | 高度 | 内容 |
|---|---:|---|
| 候选/组合行 | 48dp | 当前拼音、有限数量候选、上一页/下一页。 |
| 字符网格 | 152dp | 3行×48dp，行间4dp；每行最多10格。 |
| 区域间隔 | 8dp | 候选与网格、网格与功能行之间各4dp。 |
| 功能行 | 48dp | 删除、空格、清空、输入方式、搜索/完成。 |
| 总高 | **256dp** | 面板内部不再另加侵占预算的顶部说明或底部全局提示栏。 |

10列按48dp单元、4dp列间距及左右各8dp计算，总宽`10×48 + 9×4 + 16 = 532dp`，可放入Thor。候选数量按剩余宽度调整，不缩小热区；使用候选分页按钮完成翻页。英文网格的剩余格可以放大小写、数字/符号与光标左右，字符区域不依赖肩键。

名称层当前201dp，不能直接与256dp面板叠加。输入展开时暂时收为**128dp编辑摘要**：保留48dp标题、56dp单行名称框、分隔线及间距，隐藏原取消/保存按钮组。原菜单仍是同锚点、同宽面板，保留原始业务锚点，只按被键盘缩小的可用视口重新钳制位置；不跳居中对话框，也不把键盘塞进280dp宽的菜单内部。

Duo的高度预算为：**Name128 + 面板256 + 中间间隔8 + 上下安全距24 = 416dp**。Thor在同一组合之外余52dp。标题、错误说明和全局footer不能再叠加在该预算之外；必要错误放在输入态已有状态区域，或收起面板后在Name内展示。字体缩放时优先减少候选数量/非必要提示并让编辑摘要内部适应，不缩小48dp热区或遮住输入文字。

键盘展开期间Name不提交业务；面板收起后恢复原201dp名称层及保存/取消按钮。可见编辑摘要与键盘属于同一活动文字会话，原内容列表、其他菜单层和播放控件不能得到焦点。

搜索输入时保留查询框与必要页头，历史/建议区域按剩余高度显示；面板关闭后恢复原结果区域及焦点，不永久改变已确认的搜索页面布局。上屏输入投影显示当前查询词和方式；最近搜索复用搜索业务状态，不为本切片新增学习或同步系统。

## 5. 编辑与提交语义

| 操作 | 明确行为 |
|---|---|
| 方向/A | 字符格输入；候选格选字。选字清除组合串，焦点回到上次字符格；网格移动与文本光标移动分开，光标通过显式左右控件调整。 |
| X删除 | 先删除未提交拼音；否则删除选区或光标前一个完整码点。空内容/光标起点为无操作。插入与长度截断也不能拆代理对。 |
| Y换方式 | 仅在面板内切中文/英文；取消尚未选字的拼音，保留已提交到草稿的文字。数字/符号通过可聚焦控件进入。 |
| B，存在组合串 | 先取消未提交拼音及候选，保留已选入的草稿，面板不关闭。 |
| B，无组合串 | 收起面板并保留编辑草稿，恢复查询框或Name名称框焦点；不触发页面返回或保存。 |
| Name层再按B/取消 | 按原菜单语义取消命名、返回父层，不创建空歌单、不执行重命名。 |
| Start | 挂起当前文字会话进入播放器；B/Start返回恢复草稿。不会隐式选候选、提交搜索、创建歌单或重命名；账号改变后不恢复旧账号名称会话。 |
| 搜索 | 组合串需先明确选字或取消；使用完整已提交草稿发起搜索，关闭面板。不得默认替用户选第一个候选。 |
| Name“完成” | 只收起面板、回填名称草稿；不直接创建、加入或重命名。原Name保存按钮仍是唯一业务提交入口。 |
| 清空 | 清当前字段草稿和组合串，不清搜索历史、播放队列或持久歌单。 |

名称沿用宿主现有长度与非空校验，输入组件不另改服务限制。新建名称提供可用默认值并选中便于替换；重命名从当前名称开始。失败保留草稿，由原VM执行保存与既有事务/会话保护，键盘不直接调用Repository。

搜索必须区分**正在编辑的草稿**与**本次提交的查询词/代次**。已有请求完成时不能整份回填旧`ThorSearchState(query=旧词)`覆盖新输入；仅当提交代次仍有效时回填对应结果，当前编辑草稿保持不变。新查询取消旧请求；换账号、离开目标会话或更新提交代次后，旧响应不得恢复已关闭的面板或改写结果焦点。

## 6. 最小接口与状态边界

以下为待冻结的接口建议，不是已存在的API。文字状态使用独立叶子类型，不把草稿伪装成`ThorItem`，也不新增账号/播放状态副本。

```kotlin
enum class ThorInputContext { Content, SystemIme, CharacterPanel }
enum class ThorTextMode { Pinyin, Latin, Symbols }

sealed interface ThorTextTarget {
    data class Search(val sceneKey: String) : ThorTextTarget
    data class MenuName(val subjectKey: String, val renaming: Boolean) : ThorTextTarget
}

data class ThorTextSession(
    val id: String,
    val target: ThorTextTarget,
    val draft: TextFieldValue,
    val mode: ThorTextMode,
    val composing: String,
    val candidatePage: Int,
    val focusedKey: String,
)

interface ThorPinyinLexicon {
    suspend fun prepare()
    fun candidates(normalizedSyllable: String): List<String>
}

@Composable
fun ThorCharacterPanel(
    session: ThorTextSession,
    candidates: List<String>,
    candidatesLoading: Boolean,
    onAction: (ThorTextAction) -> Unit,
    modifier: Modifier = Modifier,
)
```

`ThorTextAction`至少包含字符输入、候选选择、候选分页、删除、空格、清空、模式切换、光标移动、完成、返回。纯reducer决定组合串、选区和焦点变化；输入Router将物理操作转换为当前上下文的动作。面板只有文字动作回调，没有播放器、网络、账号或歌单提交回调。

根层按session ID和冻结target核对草稿回填。Name菜单被关闭、对象改变或账号变化使原目标失效时，关闭关联文字会话；不能把迟到候选/完成回调写入后来打开的另一个名称框。上屏只接公开的文字预览投影，不取得可编辑会话的业务权限。

## 7. 文件归属与集成顺序

| 所有者 | 独占文件/职责 |
|---|---|
| 字符面板worker | 新增`app/src/main/java/com/ljyh/mei/thor/text/`下的`ThorTextSession.kt`、`ThorTextReducer.kt`、`ThorCharacterPanel.kt`、`ThorPinyinLexicon.kt`及对应纯测试；只接文字状态和回调。 |
| 同一worker的数据资产 | 新增`app/src/main/assets/thor/pinyin-v17.tsv`、`pinyin-v17.manifest.json`、`unicode-license.txt`和`scripts/generate-thor-pinyin.py`。根确认来源/格式后才加入，不引入大型输入法依赖。 |
| 根集成 | Search/Name会话打开、草稿/提交代次、默认名称、完成/取消语义；Lower独占路由、Name128dp输入态、键盘视口和焦点恢复。公共命令/模型变更由根统一。 |
| 平台输入owner | `ThorInputRouter`输入上下文、物理Y与媒体键区分、方向/摇杆交接、持有与失焦清理；不直接更新草稿或执行业务。 |
| 上屏owner | 根确认公开投影后显示搜索词、方式及已有最近搜索；保持三材质×日夜，不改变其他场景布局。 |

先冻结target/session、所有权和动作契约，再并行做离线字表/reducer与面板；根接入搜索，再接Name，最后接上屏投影。各worker不并发构建；由根在允许操作设备后统一构建和运行验收。当前设备冻结期间不执行安装、ADB或模拟器操作。

## 8. 十条实际验收

以下均为**待执行**。纯测试覆盖可辅助定位，不能代替实际手柄/窗口操作记录。

1. **离线中文搜索**：冷启动后关闭候选数据网络依赖，用手柄逐字输入“周杰伦”；候选选入后查询词正确，搜索执行一次，能够从真实结果进入播放。搜索服务本身可联网，候选生成不联网。
2. **多音字与ü**：在候选面板分别输入`chong`和`zhong`，可选入“重”；输入`lv`可选入对应ü读音字符，`lu`候选不因归一化错误与其整体混同；实际翻页可达后续候选。
3. **英文数字符号**：纯手柄输入包含大小写、数字、空格及常用符号的查询/名称；模式切换不改已经选入的草稿，数字和符号可返回原模式与焦点。
4. **完整字符编辑**：从已有含补充平面汉字/emoji的名称开始，在中间移动光标、替换选区、X删除、触及长度上限；无半个代理对、替换字符或光标越界，删除不触发更多菜单。
5. **B分层退出**：有拼音时第一次B只取消候选，下一次B收面板并保留草稿；Name中再按B才取消命名并回父层，恢复原入口焦点，全程无创建/重命名请求。
6. **Name提交边界**：新建有可用默认名，替换文字后按面板“完成”只回Name；按原保存按钮才创建/创建并加入一次。重命名同样不因选字、完成或返回提前写入；失败保留草稿。
7. **快捷键独占与防穿透**：CharacterPanel中Y仅切方式、X仅删除；SystemIme不把物理Y/X解释为面板动作。两种文字态的L2/R2不切歌，Select/L1/R1不切页，媒体播放键不切输入方式。Start挂起文字会话进入播放器，返回恢复同账号草稿及适用输入状态，未提前选字或提交。扳机持有退出后必须数字释放且轴归零再新按；持有A完成/关闭后不自动播放结果，失焦回来不自动输入。
8. **搜索异步草稿**：慢请求期间修改查询词，再让旧请求完成；新草稿不被覆盖。连续提交两个词、换账号或退出搜索后，旧响应不能回填错误结果或恢复旧面板，取消不显示为网络失败。
9. **双设备空间与主题**：在Thor537×468dp和Duo555×416dp实际下屏窗口打开Name+面板，验证128/256/8/24预算、最底行与候选页、长名称/错误/字体缩放；焦点不被遮住、热区至少48dp。三材质×日夜均有可读文字和焦点。
10. **恢复与数据可重复性**：收起再打开面板、切搜索/名称目标及窗口恢复后，草稿与焦点属于正确session；旧目标完成回调无效。同时从相同归档重复生成字表，源SHA与生成SHA可核对一致，断网启动候选可用，许可随资产保留。
