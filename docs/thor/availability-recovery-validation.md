# 不可播放标记与有界候选恢复

日期：2026-10-31。源码提交 `1dfc5e60`。用户澄清的目标是无版权／无权限、完全不能播放的歌曲；运行过程中发现不可用时仍尽量跳过并继续播放。

## 最终行为

接口明确拒绝播放的歌曲仍显示在列表中，标题使用次要文字色、封面减弱，右侧显示“不可播放”。条目保留列表焦点、封面预览、喜欢、收藏及加入歌单等管理能力；直接 A／触摸播放被拒绝，既有播放队列不会被清空或偷偷改播下一首。对应菜单不再提供“下一首播放／加入播放队列”。

“播放全部”、随机播放及队列插入提前排除已知不可播放条目。过滤按原始位置映射，不按歌曲 ID 去重，因此重复歌曲、指定中间项、真实播放顺序和选中歌曲都能保留。随机起点从过滤后的候选中选择。手动上一首／下一首同样跳过当前账号已知受限的队列条目。

运行时的新失败先沿用既有同曲刷新、卡顿恢复和音质降级。恢复耗尽后，按实际逻辑顺序在后台检查后续候选，只有发现可用候选才进行一次定位与准备；失败候选不成为当前曲目，也不逐首产生提示。这样避免旧逻辑收到一次错误就立即切下一首、造成快速连跳。

“音源不可用时尝试下一首”缺省开启，原有明确关闭值保留。候选都不可用或预算耗尽时才暂停并集中提示，不能保证无可用音源时仍持续播放。正常结束、队列播放和 AutoMix 的衔接路径继续保留。

## 权限数据边界

`MediaMetadata` 新增 `SongPlaybackAvailability`（Unknown／Playable／Unavailable）与安全短原因。歌曲详情、歌单、专辑、搜索、每日推荐、歌手、智能播放及 FM 的转换保留权限；独立 `privileges` 数组按歌曲 ID 合并，不依赖数组位置。

`st`、`pl`、最大播放码率及等级使用可空字段区分缺失与明确的零。沿用项目现有 RandomPlaylist 已验证契约：负 `st`，或明确 `pl=0` 且没有正向最大播放质量证据时拒绝；字段缺失、单独 fee／VIP 标记及有冲突的正向播放等级证据保持未知。未知不等于有版权保证，仍由实际完整音源解析裁决；没有对每个列表条目发起音频 URL 探测。

本地音频与播客不因在线歌曲权限提示被误拦。Thor 设备收藏、本地歌单和历史不会持久沿用旧账号权限；账号换代废弃旧队列权限投影，不修改或重新开始当前队列。运行时 HTTP、网络、临时文件和解析错误不写入永久版权黑名单。没有用试听或 VIP 标签直接推断完全禁播。

## 运行时恢复边界

- 一个恢复 campaign 最多检查 8 个候选，候选协程预算 4 秒，跨自动提交共享 12 秒预检预算；Repeat All 不会重复检查同一 entry。
- 优先使用本地源和完整缓存。零长度内容不再被误判为完整缓存，保留已有缓存本身。
- 需要网络时复用媒体 HTTP 客户端，仅读取最小数据验证资源可访问性，不写入音频缓存；HTTP call、connect、read timeout 均为 4 秒。获取一字节不等于网络只传输一字节，也不等于完成音频解码。
- 真实打开后若仍失败，沿同一有限 campaign 继续；自动定位不重置 visited。约 2 秒健康播放、正常完成或明确用户操作才清理恢复状态。
- Pause、Stop、Seek、选曲、队列编辑、顺序控制及账号变化取消旧恢复。提交前复核 generation、队列 epoch、全部 entry 签名与顺序、当前失败条目及播放意图，迟到结果不能替用户改走曲目。
- 协程超时不被当作所有底层 Socket／本地 Binder 绝对可中断的证明；HTTP 有独立总时限，提交仍受身份及取消检查保护。
- 仅最终停住时发一个聚合 `playbackFailure`。Bridge 按事件 ID、连接快照和当前 entry 去重；候选过程及成功恢复不产生逐曲错误洪泛。
