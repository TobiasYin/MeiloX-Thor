# MeiloX for AYN Thor：双屏音乐播放器设计提案 v1

初版日期：2026-10-30；输入契约修订：2026-10-31。本文定义页面、双屏分工、3D 封面与手柄交互目标，不作为全页实现或设备验收声明。当前 Thor 专用壳的输入规则以第 4 节为准；Legacy 账号兼容页继续复用既有实现与返回握手，本轮不重写账号页。输入实现范围及回归结果统一见 [控制器验证](controller-validation.md)，其他设备证据见独立验证记录。交互预览使用原创虚构内容，本轮未同步修改预览。

## 1. 产品目标与边界

把 Thor 变成一台可拿起就听、可完全用手柄浏览的专用音乐播放器。浏览时，下屏负责选择，上屏把当前聚焦的专辑、歌曲或歌单呈现为一件可欣赏的音乐藏品；播放时，下屏成为控制台，上屏成为封面与歌词共同构成的舞台。

首版音乐来源按「网易云音乐 + 本地音乐」设计。沿用当前项目的在线搜索、喜欢的歌曲、歌单、专辑、歌词、队列、下载、本地扫描等业务概念；现有接口的实际可用性仍需后续开发验证。QQ 音乐辅助歌词接口不能视为已具备 QQ 音乐账号与曲库接入。多音乐平台、音乐人中心、私信、评论与一起听不进入首版核心路径。

本文中的「连接/绑定」指连接网易云账号，以及授予本地音频访问权限。网易云账户的微信、QQ 等安全绑定属于账号管理，不能与音乐来源混淆。Thor 展示登录二维码、手机扫码授权是待验证的新方案；当前 PcQrLogin 是客户端扫描并授权电脑登录，方向相反。

## 2. 双屏职责与信息架构

**Thor 的屏幕分辨率与比例是设计的首要约束。** 上屏画布始终固定 1920 × 1080（16:9），下屏始终固定 1240 × 1080（31:27）。预览只整体缩放屏幕，不因聊天窗口宽度、文字或按钮数量加高/加宽画布；溢出内容使用屏内列表滚动或分页。原生布局仍需区分像素、逻辑密度与安全边距，不能把像素数直接当作文字 dp。

### 设备档与支持范围

| 设备档 | 上屏 | 下屏 | 系统参考 | 产品优先级 |
|---|---|---|---|---|
| AYN Thor | 6 英寸 AMOLED，1920 × 1080，16:9 | 3.92 英寸 AMOLED，1240 × 1080，31:27 | Android 13 / API 33 | 主档；首先核对该画布和双屏层级 |
| Retroid Pocket Duo（用户所称 RP DUO） | 5.5 英寸 OLED，1920 × 1080，16:9 | 4.5 英寸 OLED，1280 × 960，4:3 | Android 16 / API 36 | 次档；后续兼容的明确双屏掌机 |

首版围绕 Thor 主档设计，后续围绕 RP Duo 次档调整。不扩展到任意分辨率、折叠屏或奇异外接屏；正常的超长列表、长文本和大字号仍应通过滚动、分页和内容排布支持，不改变屏幕比例。RP Duo 上屏像素画布与 Thor 相同，但实物更小，需要复核文字可读性；下屏比 Thor 更宽、更矮，需要调整可见行数与工具栏密度，不能把 Thor 下屏拉伸复制。两档使用相同的四一级 Tab 层级与完整手柄语义，侧栏只出现在一级页。

### 两设备的预览尺度

提供「同像素缩放」与「按实物尺寸估算」两种明确标注的展示尺度。前者对该设备两屏使用相同像素缩放系数；后者按面板对角线尺寸与各自宽高比计算。每一块屏幕都维持自身原始比例，屏框、边框与铰链不计入面板尺寸：

| 设备 | 同像素缩放：下屏/上屏宽 | 同像素缩放：下屏/上屏高 | 按实物估算：下屏/上屏宽 | 按实物估算：下屏/上屏高 |
|---|---|---|---|---|
| AYN Thor | 64.583% | 100%，等高 | 56.526% | 87.524% |
| 标准 Retroid Pocket Duo | 66.667% | 88.889% | 75.0991% | 100.1321%，几乎等高 |

RP Duo 此处指官方标准 Pocket Duo，不能混入 Duo Lite/Lite+ 的尺寸。物理估算适合感受两块面板之间的大小关系，不表示已测得整机边框或铰链尺寸。参考 AVD 的 **369dpi 是模拟器逻辑 density，不是真机 PPI**，也不能用来推导上下屏实物大小或充当 RP Duo 真机 density。RP Duo 的实际 density、display ID、自然旋转方向未见于上述官方规格，后续应实读；原生布局边界以各设备实际窗口与逻辑 density 核准为准。后续先核对画布与上述尺度，再核对页面的视觉层级。

四种预览的有效显示区域已在浏览器中数值核对，宽高比偏差仅为 CSS 子像素舍入；这不代表真机适配验收。

固定四个一级 Tab 放在下屏右侧，顺序为：首页、发现、音乐库、我的。**侧栏仅在这四个一级页面存在；其他页面均隐藏侧栏，内容使用下屏完整宽度。** 搜索入口放在一级页页眉；账号连接、绑定和各类设置由「我的」承接。播放页是全局临时状态，可从内容页进入；队列可以关闭并返回原页面，两者都没有一级导航侧栏。

| 导航层级 | 页面范围 | 下屏导航与宽度 |
|---|---|---|
| 四个一级页面 | P03 首页、P04 发现、P05 音乐库、P18 我的 | 显示右侧四 Tab，内容区位于侧栏左侧 |
| 二级/详情与独立流程 | 引导、账号连接、专辑/歌曲列表、详情、歌手、搜索、本地/下载、设置、收藏与编辑等 | 隐藏右侧栏，内容使用完整宽度，保留必要返回、标题与上下文控制 |
| 播放相关临时页面 | 播放器、队列、歌词浏览 | 隐藏右侧栏，内容使用完整宽度；播放器不显示搜索等无关工具 |

```text
首次引导 → 屏幕/按键校准 → 账号连接或本地音乐 → 首页
首页：继续收听、最近播放、每日推荐、私人 FM
发现：推荐歌单、分类、新专辑、排行榜 → 列表/详情
音乐库：喜欢的歌曲、收藏专辑、我创建的歌单、收藏歌单、歌手、本地、下载、云盘、历史
我的：网易云连接/绑定、同步、屏幕/手柄/吹气、声音/外观/存储、关于
一级页页眉：搜索入口 → 沉浸式搜索输入/结果页
全局：播放器 ↔ 原内容页；队列 ↔ 进入队列前的页面
上下文：歌曲菜单、收藏/加入歌单、创建与编辑、确认对话框
```

每个一级 Tab 保存独立的返回栈、筛选、稳定列表 key 与滚动位置。L1/R1 仅在四个一级页切 Tab，恢复该 Tab 的列表记忆，不重建播放队列；其他二级页不跨级切 Tab。新进入列表默认第一项，队列也不自动聚焦当前播放项；从详情、菜单或临时页返回时恢复原列表 key 与滚动。B 先关闭最内层或返回上级；位于发现、音乐库、我的一级页时先回首页，首页再按第 4 节的两秒确认规则退出。音乐库分类、搜索类型及其他页内工具由长 Select「页面操作」访问，触摸入口保留。

区分三个状态：浏览焦点、用户确认动作、正在播放歌曲。移动焦点只改变浏览预览。A 确认歌曲才开始播放，且留在列表；A 确认专辑/歌单进入详情。播放页、队列页和歌词浏览页的上屏始终锁定正在播放歌曲。浏览时若正在听别的歌，下屏的简洁迷你播放条位于底部操作条之上，避免把预览误认成正在播放。

## 3. 视觉与动效目标

整体像精致的掌机音乐收藏柜：规整、清晰的下屏列表，轻盈、带材质感的上屏藏品展示。主信息保持稳定，动效服务于焦点与音乐节奏。

主题采用两个正交维度：品牌/材质主题包与全局 day/night。默认微砂陶瓷 Ceramic（`ceramic`），另提供晶雾 Glass（`glass`）和钛金 Titanium（`titanium`）；三包保持相同布局、焦点、尺寸和功能，各自完整覆盖白天/夜间。系统跟随/白天/夜间作用于全部页面和两屏，播放器服从同一模式，不再默认强制独立深色。白天播放器使用浅色承载面和深色歌词，夜间使用深色承载面和浅色歌词。

主方向使用 Soft UI Evolution 的微砂底、窄高光与轻接触阴影，播放按钮带精细音响控件质感；晶雾使用稳实正文底层与局部高不透明玻璃，钛金使用缎面钛银/深阳极铝、琥珀/铜强调与局部精细倒角。正文、按钮和焦点使用主题语义色，封面提色只影响环境层。完整契约见 [主题系统 v1](theme-system.md)；这是后续原生实现方案。

一级下屏采用页眉、主内容、右侧四 Tab、迷你播放条与底部操作条；二级下屏取消侧栏，保持必要页眉/返回与上下文控制，以完整宽度呈现内容。列表默认单列，按参考逻辑密度预计同时看见约 4–5 个完整条目；专辑列表可切换两列紧凑卡片。页眉压缩装饰性大标题，把空间让给音乐。行内突出标题，艺术家、年份、来源、下载状态使用次级文字；长标题聚焦后延迟滚动，不让所有文字同时移动。最终同屏数量依实际窗口、系统字号和安全边距确定。

### 横向优先的列表骨架与底部操作条

专辑详情、歌单详情、歌曲、本地与下载列表统一采用：**单行页头左侧为返回与标题/分类，右侧为必要数量或状态；中间为列表；底部操作条（dock）左侧为精简按键提示，右侧为上下文动作。** 专辑详情的曲目数量直接与专辑名同行，靠右显示「共4首」；4 是示例，实际数量随集合动态更新，不再另设「4首 · 完整专辑」副标题。音乐库专辑/歌曲/歌单列表继续使用已合并的分类页头。

「播放全部」放到底部操作条右侧，可配「随机播放」等少量次要动作，不再在列表顶部增加播放工具条。每页只设一个主要动作及少量必要次要动作；收藏、下载、排序等其余操作按上下文进入菜单。现有迷你播放条位于 dock 之上，两条均为实际存在时预留空间，列表末项不能被覆盖。没有上下文动作的页面不空留一排按钮区域。

优先使用下屏横向空间，但按钮热区仍至少 48dp，文字和焦点不得被挤压；空间不足先收起非必要提示或把次要动作移入菜单，主要动作保持可达。搜索、设置和队列使用必要的本页动作，不照搬「播放全部」；设置开关/主题仍即时保存，不凭空增加保存按钮。Thor/RP Duo 固定画布与其他状态行为不变。

### 界面文案：只呈现内容、状态与操作

产品界面只显示真实内容、必要状态和操作标签。设计意图、上下屏分工、焦点与队列状态机解释留在本文，不转成常驻界面文案。界面不出现「预览中 · 正在播放仍为……」「浏览焦点与播放独立」「上屏锁定/保持当前歌曲」等解释条，也不添加设计口号、重复副标题或「队列浏览中」角标。浏览与播放的行为规则保持不变，由实际封面、歌曲信息、当前播放标识和操作结果表达。

专辑简介、标题、艺术家、年份、曲目数等有价值内容继续保留；当前播放/暂停、下载进度、离线、未连接等实际状态也应清晰显示。来源与简介按当前上下文的判断价值取舍，不一律删除或常驻堆叠。按键条只保留当下可用的简短操作，校准步骤、权限请求、错误原因与恢复操作仍给出必要提示。新增文案应帮助用户理解内容、判断状态或完成当前操作；仅解释设计如何工作的文字不进入产品界面。

### 音乐库三类列表的紧凑单行页头

音乐库的专辑、歌曲、歌单列表统一使用同一行页头：**返回（48dp 热区）＋静态小字「音乐库」语境＋专辑 / 歌曲 / 歌单三个触摸分类入口＋右侧轻量「已收藏 · 数量」**。当前分类使用下划线与文字强调，分类已选状态与列表焦点分别表达。删除重复的「收藏专辑」等大标题、「音乐库 / 专辑」等路径和独立第二行分类。专辑/歌单详情、歌手、搜索等页面仍保留自己的标题，不套用这组三类切换。

返回与每个分类按钮均至少有 48dp 热区，文字保持可读；空间不足时优先隐藏静态语境或数量，不缩小分类文字，也不把分类换成两行。排序、筛选、视图等仍通过页内工具或上下文菜单到达，不再添加重复标题。Thor 与 RP Duo 的固定画布不变；预计省下的约 40 个设计逻辑单位交还列表，实际能增加多少内容由行高和窗口核对，不承诺新增一整行，也不表示已原生实现。

方向始终留在当前列表，不进入页头分类。长 Select 打开「页面操作」，选择专辑／歌曲／歌单分类；触摸仍可直接点页头。分类是同级替换，不增加返回栈，B 返回进入这组三类列表前的入口；切换分类按新列表从首项进入，返回已有列表时恢复稳定 key 与滚动。L1/R1 仍只在四个一级页切 Tab，不承担这组三类切换。

焦点使用双描边、柔和底色与左侧定位标共同表达，不能只靠颜色，也不另加解释焦点行为的文案。按下反馈不改变控件布局边界，防止周围内容跳动。已选、正在播放、键盘焦点是三种可区分状态。底部提示按情境显示 4–6 个最重要操作；完整映射可在设置里随时查看。

本轮按用户指定的 [UI/UX Pro Max Skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 进行需求分析、设计系统检索、UX/风格/Jetpack Compose 专项检索、适用性审核与交付检查。安装时核对的上游 HEAD 为 `28b3b8dee8c976df4fa3e94aed4e092ad43fcb03`；[Skill 来源](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 可供后续复核。

Music Streaming 产品匹配可用；生成器的 Feature-Rich Showcase 是营销落地页结构，收窄查询后仍不适合掌机，故不采纳其 Hero/CTA 布局，也不照搬 Righteous/Poppins 字体组合到中文界面。信息结构沿用下屏清晰克制的列表与上屏实体 CD 物件；最终材质主方向为微砂陶瓷 Soft UI Evolution，并抽象为 Ceramic/Glass/Titanium 三包。全局明暗遵从用户选择的系统跟随/白天/夜间，播放舞台同样完整覆盖两模式。

| 语义 Token | 白天职责 | 夜间职责 |
|---|---|---|
| 页面背景 | 当前主题的浅色材质基底 | 当前主题的深色材质基底 |
| 内容表面 | 稳定的浅色文字承载面 | 稳定的深色文字承载面 |
| 正文 | 深色文字，包含白天播放歌词 | 浅色文字，包含夜间播放歌词 |
| 辅助文字 | 保持可读的次级文字 | 保持可读的次级文字 |
| 操作/焦点 | 当前主题的强调色与对比边界 | 当前主题的强调色与对比边界 |

字体采用 Android 系统/Noto Sans CJK，数字使用等宽数字特性。间距采用 4/8dp 节奏；Android 点击区域至少 48dp，列表行建议 64–72dp，右侧 Tab 建议约 64dp 宽。普通文字与辅助正文对比度目标至少 4.5:1，承担意义的图标、控件边界和焦点目标至少 3:1；各主题、两模式和封面环境层的实际合成结果分别校核，不能用一组旧色值的计算替代。图标使用统一矢量家族与线宽，图标按钮有可访问名称。

UI 按下/焦点反馈目标约 100ms，封面切换目标 220–320ms，动画应能被新输入打断。长列表的条目身份和焦点应稳定，异步封面加载预留空间；后续 Compose 实现可使用稳定条目标识验证这一要求。以上均为设计约束与目标，本轮未交付原生 UI、未进行设备或帧率测试。

### 3D CD 盒

封面载体是有厚度的实体 CD 盒：正面和背面均贴当前封面图，背面文字不镜像；侧面具有书脊、半透明边缘与柔反射，可用艺术家/专辑名形成书脊信息。无真实背封时重复正封即可，不伪造曲目表。必须能从斜角看见深度，不能用二维卡片翻转冒充盒体。

静置时缓慢上下悬浮，并有柔和投影与封面颜色环境光。吹气阶段绕 Y 轴固定正方向累计旋转，力度越大角速度越高；停吹先惯性减速，再柔和吸附到相对正面的正/背面展示角。直接触摸/鼠标拖动也能拿起并转动盒体，释放后使用同一惯性与吸附，具体初值见第 6 节。浏览切换时，新盒体滑入中央展示位，前后相邻封面以弱化轮廓提示方向。快速连发期间只跟随最后焦点更新文字，减少反复加载。初始动效建议：单步过渡约 220–320ms，悬浮周期约 6–9 秒；这些是视觉起点，需在模拟器和真机上调校，并非已验证性能指标。

播放时封面居左、歌词居右，封面占上屏约 40%，歌词约 50%，余量用于边距。背景为从封面提取的低频流动光带/雾状颜色，强度低于歌词与盒体。暂停后环境动效缓慢降低；减少动态效果模式停止连续旋转、惯性、弹簧过渡、悬浮、视差和流动，直接使用相对正面的静态展示角，手动操作仍有离散等效方式。无封面时使用统一的磨砂盒与曲名，不显示破图。

## 4. 全局手柄契约

本节为本轮确认的原生输入契约，实现与回归范围以 [控制器验证](controller-validation.md) 为准。除定位当前统一收至页面操作菜单外，其他触摸按钮与手势保留；方向导航和独立快捷键共同覆盖其操作。当前原型仍保留历史交互，不能以原型旧跨区行为替代本节规则。

| 按键 | 正常页面行为 | 必须保持的规则 |
|---|---|---|
| 方向键 / 左摇杆 | 只移动当前列表或显式选项 scope | 不进入 Tab、页头、页脚、迷你「正在播放」；到边界停止，新按也不越区。未登记 scope 时不退回 Compose 全局空间寻焦 |
| A | 确认当前有效项 | 歌曲立即播放并留在列表；集合打开详情；Player 主焦点为播放/暂停，seek 主焦点为应用 |
| B | 关闭最内层、返回，或首页二次退出 | 菜单/编辑先关闭或取消；其他一级页先回首页；首页首次提示，两秒内第二次独立按压才退出，重复 DOWN 不算第二次 |
| X | 当前条目菜单 | 只作用于当前有效条目，不再用无对象 X 打开页面级工具；触摸长按/更多仍可打开同一条目菜单 |
| Y | 播放 / 暂停 | 只控制当前歌曲，文字编辑等独占区域按自身规则拦截；Player 与 A 作用于同一主播放按钮 |
| L1 / R1 | 四个一级页切 Tab；正常 Player 保留进度快捷键 | 一级页 Press 立即切 Tab；正常 Player 短按±15秒、长按预览及松开应用维持原肩键合同；其他二级页不跨级 |
| Start | 全局优先进入 / 退出播放器 | 普通菜单关闭；seek 取消未提交预览；Name 挂起同账号名称草稿，返回恢复，不自动创建或重命名 |
| Select 短按 | 松开时打开 / 关闭队列 | DOWN 不立即开队列；返回原入口列表 key 与滚动；不多层叠加队列 |
| Select 长按 | 满 500ms 打开「页面操作」 | 每次完整手势只发一次 PageActions，长按后 UP 不再开队列；失焦/reset 取消，迟到 UP 不执行 |
| L2 / R2 | 上一首 / 下一首 | 保留数字键与模拟轴共用归零锁存，一次完整行程一次，不连切也不快进 |
| L3 / R3 | 随机播放 / 播放全部 | 仅当前集合/详情有对应真实批量动作时生效，使用与触摸按钮相同的集合快照 |

**列表焦点。** 新进入任何内容列表默认第一项，包括 Queue；每次提交新的搜索结果也从首项开始，不沿用上一查询的结果焦点。当前播放标识与焦点独立。返回已访问列表则恢复稳定 key 与滚动位置；原项删除时按列表有效项规则恢复。方向、HAT 与左摇杆仅在该列表的完整逻辑索引中移动，未组合行先滚动再请求焦点；持续持有到边界停止，不首尾循环。松开再按仍留在同一 scope。触摸选中后，手柄从该列表的有效对象继续。

**页面操作。** 分类、搜索/编辑查询、刷新/重试、导入/扫描、新建歌单、定位当前项，以及 Player 的进度编辑、播放模式、歌词、定时等页面级按钮，都有长 Select 菜单中的独立动作或原有直接快捷键。按当前页面、权限及能力列出真实可执行项；菜单上下选项、A 执行、B 关闭并恢复原列表。页头、右侧 Tab、底部按钮与迷你播放条继续接受触摸，方向键不在这些区域间游走。队列和歌词的「定位当前」唯一入口为长 Select「页面操作」内的独立动作，不再提供独立底部按钮；进入队列不自动定位。

**Player 与 seek。** 正常 Player 的唯一控制器主焦点是播放/暂停，A/Y 播放控制，方向不进入进度、信息栏或底部功能行。其他按钮经长 Select 或既有独立快捷键操作。显式 seek 编辑只保留 Apply 主焦点：A 应用、B 取消、左/右各减/加 10 秒，上/下不移动焦点；预览不提前 seek。正常 Player 的肩键临时预览保持自身松开提交合同；显式 seek 中再次长按肩键，也沿用松开提交，A/B 与方向键合同不排斥该独立快捷路径。进入 seek 不重置肩键持有，以免打断正在发生的 hold。

**显式选项和文字区域。** Appearance、Controls、Timer 只在已登记的选项区域使用 Spatial 导航，不包含返回键、页头和页脚。Name 明确限定在名称字段、取消/保存及其文字面板的编辑区域；不回落到背景内容或其他页面按钮。System IME 的方向/文字/Enter/系统 Back 由 IME 所有，字符面板使用独立文字 scope；未退出文字独占时，Select 页面操作与队列均不穿透。Start 可挂起文字草稿进入播放器，返回恢复同账号草稿。

**返回和退出。** 临时页仍按入口返回：R 为原浏览页，P 为 Player，Q 为 Queue；Start 走 R→P→R，短 Select 松开走 R/P→Q→原入口，Q 中 Start 关闭 Q 后进入 P，保留原浏览返回目标。B 从二级逐层返回；其他一级页的 B 先回 Home。Home 第一次 B 只提示，再次独立按 B 在 2,000ms 窗口内才退出，重复/持有 DOWN 不续期也不确认。任何其他实际按键或有效摇杆/扳机输入、触摸、导航、切页、后台或失焦都清除退出计时；静止 neutral 报告和漂移不算新输入。

**原有肩键与扳机边界。** 肩键仍输出 Press、Tap、HoldStart、HoldStep、Release、Cancel；长按 320ms、后续每 50ms 最多一步，不补积压，换曲/失焦取消，旧肩 Release 不提交另一方向的预览。L2/R2 归一化轴达到 0.55 触发，数字释放且轴回到不高于 0.05 才重新待发；低/中行程抖动不能连切。A/B/X/Start 等不随系统 repeat 重发，Select 独立按完整长短手势处理。阈值和实体手感以实际设备验证为准。

A 播放歌曲时，以当前筛选/排序后的逻辑集合及所选索引建立队列快照；后续浏览刷新、筛选和重排不改变该队列。条目 key、队列 entryId、当前播放项和列表焦点分别维护。

**条目菜单保持原合同。** 上下选择有效项、A 执行、B 返回；A/右进入子层，B/左回父并恢复入口项。Name 只在明确编辑区域处理文字和保存/取消，busy 时不重复提交。弹层独占输入，导航与菜单 scope 切换 reset 持有输入，关闭恢复来源列表，不让旧方向或 A/B 穿透背景；进入 seek 保留肩键 hold。定位当前以外的触摸 UI 均保留。

### 音乐管理实体、菜单与持久状态

| 实体 | 归属与操作 | 与其他实体的关系 |
|---|---|---|
| 喜欢的歌曲 | 单曲的喜欢/取消喜欢，按来源与歌曲 ID 标识 | 喜欢一首不自动收藏专辑；取消喜欢不删音频或移出队列 |
| 收藏专辑 | 整张专辑的收藏/取消收藏，按来源与专辑 ID 标识 | 收藏专辑不等于逐曲喜欢，也不自动下载或加入队列 |
| 播放队列 | 当前播放会话内的有序条目，每项有独立 `entryId`，当前位置为 `queueIndex` | 与持久歌单独立；同曲可有多条队列项，入队不等于收藏或保存到歌单 |
| 持久歌单 | 我创建的歌单及其有序歌曲成员，或对他人歌单的收藏 | 只有自己的歌单可重命名、改成员；收藏歌单可取消收藏，不改原作者内容 |

喜欢、收藏、歌单名称/成员与收藏歌单关系需要持久保存；歌曲列表、专辑详情、播放器、菜单和音乐库数量共享同一份状态。切主题、切页与重新打开后不能恢复成旧图标。写入失败不显示假成功；从喜欢/收藏列表移除当前焦点项后，焦点落到相邻有效项，当前音频继续。重复加入持久歌单按来源 ID 去重并保留原顺序，不按歌名误合并不同版本。

触摸长按条目约 420–500ms 打开上下文菜单；预览移动超过 8px 即取消长按识别，滚动/拖动不触发，原生阈值后续按输入与逻辑距离校准。菜单锚定长按位置，打开后不随手指持续漂移；靠边时向内避让并限制在所属下屏可用范围内，必要时菜单内部滚动。抬手不穿透成播放或误选菜单项。手柄 X 或 More/更多以焦点条目/触发按钮为锚点打开同一菜单，菜单冻结对象 ID，后台切歌不会把操作转移到另一首。

上屏 3D 模型热区优先直接操控，不注册抢占拖动的长按菜单；对象管理通过下屏条目或更多入口到达。菜单只显示对象适用动作，文案尽量短：

| 对象 | 核心菜单动作 |
|---|---|
| 歌曲 | 喜欢/取消喜欢、下一首播放、加入队尾、加入歌单、查看专辑；下载等按能力补充 |
| 专辑 | 收藏/取消收藏、播放、下一首播放整张、加入队尾、加入歌单 |
| 我创建的歌单 | 播放、重命名、加入歌曲；成员菜单使用「从歌单移除」 |
| 收藏歌单 | 播放、取消收藏、查看；不显示重命名或修改作者歌单 |

「下一首播放」在当前 `queueIndex` 对应条目之后插入，不能搜索到第一首同曲就插入；专辑按曲目顺序插入整张，「加入队尾」追加到末尾。队列焦点、移除、移动和撤销均按独立 `entryId` 定位，位置变化时更新 `queueIndex`，队列允许同曲的多条记录，不因歌曲 ID 相同而隐式合并；重复同曲不混淆当前播放或焦点。喜欢/收藏、入队与加入歌单都不切换当前曲；只有明确的播放动作会开始或切换播放。无当前曲时，入队只建立待播内容，等待明确播放。专辑加入歌单展开为歌曲成员；整张曲目尚未读取时先读取，失败可重试，不用假条目占位。

加入歌单采用同锚点、同宽浮层内的二级菜单，只列可编辑的我创建歌单。↑/↓ 选择目标，A 即加入并关闭，已包含的歌曲不重复写入；单曲为一个源条目，整张专辑为有序源集合。B/← 返回父菜单并恢复「加入歌单」高亮，返回不修改。二级「新建歌单」进入轻量命名层，名称默认可用；保存即原子创建并加入，取消不残留空歌单。独立创建歌单页仍以明确的「保存」创建，可为空歌单。多目标批量添加只作为后续扩展提案，不是当前常用流程。

父/子层约 170ms 水平过渡，输入与高亮立即响应，新输入可中断旧过渡；不先跳居中对话框，也不并排挤成两列。Thor 与 Duo 使用同一原始锚点，按屏幕边界钳制并保留菜单内部滚动。减少动态时直接替换层级。普通喜欢/收藏、入队、加入歌单、重命名和从歌单移除提供精简的完成反馈与撤销；撤销只还原本次修改，不回滚音频，队列撤销只移除该次尚未播放的插入条目。

未登录/离线允许保存本地喜欢、专辑收藏和本地歌单；远程音频是否可播仍按资源实际状态判断。本地保存不能显示成云端同步成功。未来账号同步必须真实连接后明确处理本地与账号关系、去重/冲突及失败重试，不把本地修改悄悄归给其他账号。本轮预览仅模拟本地持久状态与代表性管理流程，不宣称网易云登录或同步已接通。

## 5. 页面设计与用户故事

### P01 首次引导与屏幕/按键校准

**用户故事：** 第一次打开应用时，我希望知道两块屏分别做什么，并确认按钮位置，快速开始听歌。

**上屏：** 展示产品标识和缓慢悬浮的示例 CD 盒，进入校准后显示醒目的「上屏」与方向标记。**下屏：** 三步短流程：确认屏幕角色、确认 A/B 与肩键、选择连接网易云或使用本地音乐。吹气介绍可跳过，不默认索取麦克风权限。

**手柄：** 方向只在校准的显式选项区域移动，A 继续，B 返回上一步；按键校准阶段仅记录与验证，不触发全局控制。下屏触摸仍可选择「上下屏反了」。

**空/失败：** 未检测到第二屏时允许继续单屏，提示在设置里重新校准。手柄未识别时保留触摸流程。**验收：** 无账号可完成引导；校准结束后角色与按键提示一致，重新打开不重复引导。

### P02 账号连接与本地入口

**用户故事：** 我希望连接自己的网易云收藏，也能跳过登录直接播放设备中的音乐。

**上屏：** 显示网易云连接状态、账号头像与同步状态；若后续验证支持展码登录，这里展示二维码及有效期。**下屏：** 网易云连接卡、本地音频权限卡、当前连接状态、刷新与退出登录。可用的手机号/网页/Cookie 路径按能力展示，Cookie 放高级方式，不作为首屏主按钮。

**手柄：** 在本页连接/权限列表中选择并用 A 执行；X 只作用于有效账号条目，其他页面级动作由长 Select「页面操作」到达，B 返回。自有文字输入使用明确编辑区域；外部 WebView、验证码与系统授权另行验证，不据应用内 scope 宣称这些第三方环节已适配。

**空/失败：** 登录失效显示「重新连接」，保留本地与下载入口；同步失败可重试，已缓存列表仍可看。**验收：** 登录前后状态清晰；退出登录不会删除本地文件；不会把关注/粉丝或安全绑定误当音乐源。

### P03 首页

**用户故事：** 打开掌机后，我希望很快继续上次听的内容，或选择一份当天推荐。

**上屏：** 聚焦「继续收听」时显示上次歌曲 CD 盒与播放进度；聚焦推荐时显示对应封面、推荐理由与简短介绍。**下屏：** 按顺序展示继续收听、最近播放、每日推荐、私人 FM、小量精选歌单。以分组列表为主，避免多行横向滚动争抢方向键。右栏首页高亮。

首页与发现的底栏仅保留精简按键提示和刷新，刷新热区与底栏高度均为48dp；不常驻「本地音乐」按钮。本地音乐入口统一放在音乐库，导入与扫描仍由音乐库及本地列表承接。

**手柄：** 方向仅浏览首页列表，A 继续歌曲/打开集合，X 操作焦点条目，Start 进入 Player，Y 控制当前播放；长 Select 提供搜索、刷新等页面操作。首页首次 B 提示，两秒内再独立按 B 才退出；其他实际输入、触摸、导航或后台清除计时。 **空/失败：** 新用户可连接网易云或前往音乐库选择音乐；无网时优先本地最近播放与已下载内容。**验收：** 恢复播放不丢原进度；浏览推荐不会切换正在播放歌曲；一屏内可找到继续收听。

### P04 发现

**用户故事：** 我希望按心情、曲风或新发行内容寻找音乐，并在确认前看清它是什么。

**上屏：** 当前歌单/专辑 CD 盒、名称、作者/艺术家、年份、简介；分类入口聚焦时展示分类名称与代表性封面组合。**下屏：** 页内工具栏包含精选、分类、新专辑、排行榜；主体是当前分组的列表或两列卡片。筛选用独立焦点弹层，不占 L1/R1。

### P12 双屏播放页

**用户故事：** 我希望放下操作时欣赏封面与歌词，想控制音乐时一眼找到按钮。

**上屏：** 左侧悬浮 CD 盒，右侧当前歌词与前后文，底部小字曲名/艺术家；背景低强度流动。逐字歌词以当前行亮度与词内进度表达。当前行24、相邻行22、译文14，主行另以字重与颜色强调；译文及发音提前占位并显示，切行不插入或移除辅助内容。右侧歌词减少外层上下留白，顶部与底部使用真实透明度渐隐，中心保持清晰，首末行都能进入清晰区域；左侧封面几何保持原布局。没有歌词时扩大封面与歌曲信息，可切纯封面模式。

歌词排版统一读取 `foundation.lyricLayout`：行间距16、每行上下内边距各8、主歌词与辅助内容上间距8、辅助内容之间间距6，行高1.5em；间距使用设计逻辑单位，原生按实际窗口映射。每行可点击热区至少48dp，允许按内容增高，不靠放大字号拉开行距，也不缩小热区。

上屏歌词可上下拖动，独立查看前后内容；拖动及惯性滚动都不改变播放进度、当前队列或实际播放行高亮。全部滚动停止后开始15秒计时，期间再次操作重新计时；到期回到此刻实际播放行并恢复跟随，暂停状态也能按时回到当前行。单击有有效时间戳的歌词行，从该行继续播放，暂停时同样恢复播放；执行前复核渲染时捕获的 `entryId` 仍为真实当前项，过期或隐藏旧手势不跳转新曲，不重建队列。拖动释放不能穿透成单击。减少动态时自动恢复直接定位，不播放滚动过渡。界面不新增「浏览中」或恢复倒计时等解释文案。

**下屏：** 独立播放控制台，使用完整宽度，无侧栏、无列表 dock，也不重复当前迷你播放器。当前歌曲的喜欢状态与库中歌曲、菜单共享；点击喜欢只切换该歌曲状态。自上而下按以下关系组织：

- **64 逻辑高的信息栏：** 返回与曲名/艺术家成组左对齐，曲名、艺术家各一行；右侧喜欢与更多。不再另设常驻「正在播放」泛标题。
- **紧凑主控制组：** 进度/当前时间/总时长与紧邻的上一首、播放/暂停、下一首横排形成一组。组内间距固定且克制，禁止使用 `margin:auto` 将控制区撑成长段空白。进度编辑的「取消/应用」就近使用该控制组。
- **下一首与队列行：** 展示真实下一首的缩略封面、歌曲信息，以及「队列 · 数量」入口；数量动态反映实际队列。没有下一首时显示必要空态，不复制当前曲信息充当下一首。
- **底部功能行：** 播放模式、歌词浏览、定时停止三项全宽均分，每项至少 48dp 热区。音量使用设备音量键，或从更多入口调整，不另增音量页面。
- **最下方：** 仅一处简短手柄提示，不在右侧继续堆放列表式动作按钮。

设计基线为 Thor 下屏 537 × 468、RP Duo 下屏 555 × 416 个设计逻辑单位；这是版式核对基线，不是 RP Duo 实际 density 结论。两档保持固定屏幕画布，较矮空间优先缩减区域留白，不拉长主控制区、不改变控件关系。界面只呈现上述真实内容、状态和操作标签。

**手柄：** Player 仅播放/暂停为主焦点，A/Y 播放控制；方向不进入进度、信息栏、队列入口或底部功能行。长 Select「页面操作」提供进度编辑、播放模式、歌词、定时及其他可用页面动作；短 Select 松开为队列，Start/B 回来源，L2/R2 仍切歌。正常 Player 肩键短按±15秒、长按临时预览及松开提交保持原合同；显式 seek 编辑仅 Apply 为主焦点，A 应用/B 取消，方向左/右±10秒、上/下不移焦点；若再次长按肩键仍可松开提交，不在进入 seek 时 reset 肩键。触摸控制台全部保留。 **空/失败：** 缓冲显示等待状态且保留取消/下一首；播放失败给重试、跳过与查看原因；无队列显示去首页/音乐库。**验收：** 两行曲目信息与控制组关系清晰；下一首和队列数量真实；无重复迷你播放器或列表 dock；切歌后封面、歌词、标题同属一曲；进度编辑可取消；上屏歌词拖动不seek，全部滚动停止15秒后回当前行，单击只跳转仍匹配的队列项并恢复播放，拖动释放不误触；歌词行热区至少48dp，字号与间距符合token；上屏没有必须触摸才能完成的控制。

### P13 播放队列

**用户故事：** 我希望调整接下来听什么，同时继续看当前歌曲的歌词。

**上屏：** 当前歌曲的封面与歌词，队列焦点移动不换封面，不加浏览模式解释条或角标。**下屏：** 当前曲、即将播放、已播历史分区；显示队列来源、随机/循环/自动续播状态。当前条目与聚焦条目分别标记，使用 `entryId` 与 `queueIndex`，不把相同歌曲的重复条目当成同一个焦点。

**手柄：** 新进入 Queue 默认第一项，返回已有 Queue 恢复 entryId 焦点与滚动，不自动跳当前曲；「定位当前」只从长 Select 页面操作菜单执行，独立底部按钮已移除。A 跳到所选 occurrence，X 为该条目菜单；短 Select 松开或 B 关闭回原入口，菜单/移动编辑先分层退出。方向只在队列或显式移动选项内操作。

**清空规则：** 菜单使用「清空待播」，确认后只删除后续项，当前曲继续、已播历史保留为记录。当前曲结束时，顺序模式停止；单曲循环继续当前曲；列表循环因循环候选只剩当前曲而继续循环当前，已播历史不重新纳入。自动续播开启时，清空后不会立即补曲，界面提供「继续推荐」供主动选择。

**空/失败：** 空队列提供添加音乐入口；远程队列显示已加载/待加载，补载失败可重试。**验收：** 改队列不重置当前进度；关闭精确返回入口；随机模式下显示顺序与实际后续播放一致；清空待播不误停当前曲或立即回填推荐。

### P14 歌词浏览与校准

**用户故事：** 我希望查看前后歌词、选择译文，或修正歌词偏移，不打断听歌。

**上屏：** 仍跟随实际播放；手动浏览歌词不会自动拖走上屏。**下屏：** 中间为可滚动歌词列表，页头保留必要标题与状态；译文/发音、字号与时间偏移通过本页选项到达。「定位当前」仅从长 Select 页面操作菜单执行，不再保留底部独立定位按钮。选中有时间戳的行后，A 或单击该行从该处继续播放；底部仅保留适用提示，不为定位当前重复排列按钮。数值编辑仍按自身应用/取消合同执行。

**手柄：** 方向只浏览歌词列表，A 对有时间戳行确认跳转；长 Select 提供唯一的「定位当前」入口，以及歌词来源/显示和偏移等可用页面操作，X 只作用于真实条目菜单。偏移编辑在显式选项区域提交/取消，B 回 Player；歌词行触摸仍可用，定位当前不再有独立底部按钮。 **空/失败：** 无歌词显示重试与纯封面模式；无时间轴歌词只浏览，不提供伪造的跳转。**验收：** 滚动不改变播放；只有确认跳转才 seek；歌词来源切换失败可恢复原版本。

### P15 更多操作、收藏与加入歌单

**用户故事：** 我希望对当前选中的音乐收藏、下载或加入下一首，并知道操作是否成功。

**上屏：** 普通浏览时维持操作对象预览；从播放器/队列打开时维持当前歌曲舞台。**下屏：** 锚定长按位置或焦点项的上下文菜单，以对象名称作短标题；歌曲与专辑使用各自适用动作，喜欢与收藏文案/图标反映真实状态。一级「加入歌单 ›」进入同锚点/同宽浮层内的二级歌单列表，不先弹居中选择器、不并排占两列；约 170ms 水平切层，减少动态时直接替换。

**手柄：** X/更多打开并高亮首个有效项；↑/↓ 循环有效项并滚动跟随，A/→ 进入「加入歌单」二级，A 对目标歌单立即加入并关闭，B/← 返回父层且恢复入口高亮。二级「新建歌单」进入默认名称可编辑的命名层，保存原子创建并加入，取消返回且不留空歌单；Start可挂起名称草稿进入播放器，B/Start返回后恢复草稿，不提前保存。输入即时响应，可中断切层动画；显式高亮与业务状态并存，背景独占屏蔽；普通操作菜单中Start关闭菜单并进入播放器。**空/失败：** 无歌单提供新建；未登录/离线先本地保存，不能显示虚假的同步成功；写入失败保留可恢复状态，已包含不重复写入。**验收：** 键盘/演示按钮可完成上下、A/→ 进子层、A 加入、B/← 返回及新建保存/取消；连续输入不等待动画，同锚点边界避让在两设备正确；浏览器 Gamepad 适配不等于已验证实体手柄或 Android；3D 拖动不被抢占，关闭恢复原条目，加入不打断播放且可撤销。

### P16 创建与编辑歌单

**用户故事：** 我希望纯手柄整理自己的音乐，并能撤销尚未确认的修改。

**上屏：** 歌单盒体、名称与数量；新歌单使用中性封面。**下屏：** 独立创建页含名称、可见性与保存；我创建的歌单可重命名、添加歌曲、排序及「从歌单移除」，移除只改歌单成员，不删文件、不取消喜欢。收藏歌单只提供取消收藏等适用管理。歌曲移动为独立模式，只给出当前所需的确认/取消按键，不添加常驻编辑理念说明，不复用全局切歌键。

**手柄：** Name 只在名称字段、取消/保存及字符面板组成的明确编辑区域操作，A 按字段或保存动作执行；不让方向进入背景列表、页头或页脚。Start 挂起同账号草稿进入 Player，返回恢复。普通编辑页未保存离开需保存/放弃/继续编辑；从加入歌单新建时取消不留空歌单，保存一次完成已支持的创建并加入。 **空/失败：** 空名称提示补全；保存失败保留草稿；只读收藏歌单不展示无效编辑按钮。**验收：** 能完成创建—加歌—重命名—排序—移除与撤销；取消不提交；本地持久状态重开可读，真实账号同步尚未接通时不声称成功。

### P17 专用播放器设置

**用户故事：** 我希望让显示、按键与声音符合自己的使用习惯，并随时恢复到可用状态。

**上屏：** 当前设置的实时视觉示例，调整动效时展示同一个示例盒体；必要的选项含义与影响仅在相关设置项提供。**下屏：** 分组列表：外观与主题、播放舞台、歌词、手柄与焦点、吹气与校准、屏幕角色/省电、声音/输出/均衡器、下载/存储、账号与关于。

**手柄：** Appearance、Controls、Timer 仅选项区域采用显式 Spatial scope，A 开关/选择，B 逐层返回，方向不进入返回键、页头、页脚；其他设置分类列表仍只做列表导航。校准、刷新/重试等页面操作由长 Select 或现有独立键到达，触摸控件保留。开关与主题即时保存，B 不撤销已保存设置；单独数值编辑按其应用/取消语义处理。

**空/失败：** 不支持的输出/硬件选项说明原因并禁用；显示重新校准失败保留上次可用配置。**验收：** 可全手柄开启减少动态效果、关闭吹气、重跑校准；设置改动有即时预览及清晰保存语义。

### P18 我的

**用户故事：** 我希望在一个固定入口查看网易云连接状态，并管理这台播放器的屏幕、手柄、声音与存储。

**上屏：** 账号头像/昵称、网易云连接与同步摘要，以及相关设备/设置的当前值；搭配静态装饰封套，不使用浏览专辑的连续悬浮效果，不附加装饰或分工说明。

**下屏：** 第四个一级页面，右侧栏「我的」高亮。内容为分类列表：账号头像与网易云连接/绑定状态、同步/重试、设备（屏幕、手柄、吹气）、声音、外观、存储/下载、关于。连接和设置项打开无侧栏、完整宽度的二级页；搜索仍由一级页页眉进入。账号安全绑定与音乐来源连接使用明确不同的文案。

**手柄：** 方向只浏览「我的」分类列表，A 打开二级页，X 为有效条目菜单，长 Select 提供本页可用操作；L1/R1 在四个一级页切 Tab。我的一级页 B 先回首页，二级 B 返回「我的」并恢复原行 key 与滚动，不进入侧栏焦点。

**空/失败：** 未登录时显示「连接网易云」，设备与本地设置仍可用；同步失败显示最近成功时间与重试，不隐藏已有资料。**验收：** 可纯手柄从「我的」完成连接入口、同步重试、屏幕/吹气设置与返回；只有四个一级页显示侧栏，所有二级设置/账号页无侧栏，肩键不会跨级跳页。

## 6. 吹气与模型直接操控提案

默认关闭，在设置中明确开启并校准；首次启用时再申请麦克风权限。校准分为安静环境基线、一次轻吹、一次较强吹气，提供强度条与可跳过说明。识别只需本地短时音量/气流特征，不录制或上传语音；此处是预期方案，具体识别效果需真机评估。

**封面旋转独立于选中与播放。** 在已开启吹气、适合展示 CD 盒的前台页面中，纯吹气只驱动盒体绕 Y 轴固定正方向累计旋转，不自动切换专辑、不移动列表焦点、不确认、不改变播放或队列。两面始终贴同一当前封面，不能在旋转时切换成其他专辑。结束时回到相对正面的展示角，不停在难以观看封面的侧面。

气流经校准标准化为 0..1，再平滑为强度 `s`。目标角速度为 **`600 × s^1.45 °/s`**，输入 attack 约 **80ms**，角速度加速约 **200ms**；停吹后先按约 **420ms 阻尼时间常数**惯性减速。随后根据当前角度与约 **180ms 余速投影**，选择最近的正/背面展示角，以临界阻尼弹簧柔和吸附。最终合成 `rotateY` 精确为 **`-16° + k × 180°`**，保留 16° 轻透视；基础 `preferences.angle` 仍可调，但局部吸附目标必须扣除它，不能再次叠加基础角。质量归一化时，自然频率初值 **8rad/s**、阻尼初值 **16**。收尾可有余速造成的小幅回摆，但不生硬跳角或反复摆动。固定正向只约束吹气驱动阶段，不能阻止收尾吸附所需的小幅调整。上述值均为可调设计初值，不是实测结论。

手指/鼠标水平拖动让模型绕 Y 轴跟手双向转动，垂直拖动提供受限的小幅俯仰。触摸按下立即接管正在进行的吹气、惯性或吸附；通过轻微抬起/缩放与接触阴影变化表达拿起，布局热区和周围内容不移动。释放时估计拖动速度，继续惯性减速并使用同一投影与弹簧吸附，俯仰也柔和回到展示姿态。拖拽不改变当前选中或播放；未来原生可用右摇杆提供等效模型调整，不能把功能做成手势独占。

列表加速仍为另一条独立规则：在支持连发的列表/专辑网格中，用户同时持续按住方向键或偏转左摇杆时，方向决定移动，吹气强度可提高连发速度。松开方向或摇杆归中立即停止列表加速；到列表 scope 边界停止，松开再按也不进入页头、页脚、迷你条或 Tab。它不把旋转角度、圈数或减速完成绑定为选中事件。失焦、打开模态、合盖或进入后台停止气流采集与相关动作；只有列表加速需要采集时，松方向即可停止该采集，不能因此把单独旋转也限定为必须按方向。

当前交互预览通过设备画布之外的力度滑杆和有限时长脉冲演示输入，不申请麦克风权限，不接入麦克风或 Android 逻辑。模型使用原生语义 button 承载，聚焦模型时提供键盘左右/Enter 的等效旋转；拖拽和键盘操作不会触发歌曲确认。减少动态时关闭惯性与连续旋转，操作直接切换到相对正面的展示角。真机仍需验证噪声、外放干扰、麦克风校准、触摸/手柄手感、误触与功耗。权限拒绝或吹气关闭时，普通方向连发与全部听歌操作完整可用；模型旋转不是任何核心流程的必要操作。

## 7. 异常、生命周期与可达性

| 情况 | 产品预期 |
|---|---|
| 上屏暂时丢失 | 音乐继续，下屏显示轻提示并保留控制；提供单屏封面/歌词视图与重新连接 |
| 下屏暂时丢失 | 音乐继续，上屏出现简化可手柄控制的恢复界面；Start 可进入单屏控制，不能只剩无按钮的舞台 |
| 屏幕重新连接 | 重新核对上下屏角色，恢复原页面/进度，不重复播放、不重建队列 |
| 网络不可用 | 显示离线状态；本地与下载可用；远程失败可重试，不能清空收藏缓存 |
| 会话失效 | 当前可播放内容不中断；收藏/同步提示重连，重连后恢复原操作上下文 |
| 无封面/无歌词 | 使用中性立体盒、歌曲信息与纯封面模式，不保留空白错误区域 |
| 曲目不可播 | 解释会员/地区/资源/文件失效等已知原因；提供重试或下一首，不虚构替代音源 |
| 耳机拔出 | 默认暂停；重新插入默认不自动恢复，防止意外外放；可在设置中调整后续策略 |
| 合盖/锁屏 | 默认继续音频、停止视觉动画与麦克风采集；是否能后台持续与合盖事件识别须实机验证 |
| 来电/其他音频抢占 | 遵循系统音频焦点；恢复时保持曲目和进度，不强行抢回输出 |
| 应用恢复/旋转/进程重建 | 恢复队列、进度与最近页面；确认输出条件后再按用户偏好决定是否自动播放 |

所有错误提示都应具备返回路径；重试不抢焦点，不用自动消失的文字承担唯一恢复入口。大字号下允许降低同屏列表项数；歌词主行不因双语开启而缩得过小。减少动态效果与减少透明度互相独立。触摸和手柄共享同一操作语义，长按拖动均有菜单等价路径。

## 8. 设计验收路径与后续验证范围

本轮验收只确认信息架构、视觉方向、状态规则和操作契约，不把概念预览当原生实现。交互预览只覆盖代表性页面与局部切换。Thor 预览始终固定上屏 1920 × 1080、下屏 1240 × 1080，只整体缩放；聊天窗口变窄时也不扩画布，内容溢出由屏内滚动/分页解决。先核对屏幕比例，再核对上层 UI。设计确认后，优先验证以下完整旅程：

全手柄是应用自有页面与核心听歌路径的硬性目标。本地和已连接账号路径可作为完整核心验收；外部网页登录、验证码与系统授权的可达性应在开发前验证。若对外承诺从首次启动到登录播放的全流程手柄，就必须解决全部外部环节，不能用触摸要求替代验收。本轮尚未实现或验证该目标。

1. 跳过登录 → 授权本地 → 扫描 → 专辑 → 曲目 A 播放 → Start 播放器 → Select 队列 → 返回原列表。
2. 我的 → 网易云连接 → B 回一级 → B 回首页 → 推荐/歌单详情 → 收藏/加入歌单 → 播放 → 返回一级后肩键切 Tab，保留列表 key、滚动与队列。首页首次 B 提示，其他输入清计时，只有两秒内再次独立 B 才退出。
3. 长 Select 编辑查询/切搜索类型 → 在明确文字区域输入中文 → 结果列表 → 专辑 → 播放 → 页面操作进入 seek，方向±10秒/B取消 → 再进入并A应用。
4. 吹气关闭/拒绝权限时完成全部浏览；吹气同向加速、停吹先惯性减速再吸附至相对正面；拖动立即接管、释放按余速收尾，键盘/未来手柄具有等效操作，均不误选/误播；方向+吹气的列表加速在当前列表 scope 内独立验证，减少动态时直接切换静态展示角。
5. 三主题在白天/夜间下完整覆盖浏览与播放、减少动态/透明度、无歌词、无封面、离线、会话失效与失屏恢复。
6. 喜欢歌曲/收藏专辑 → 库中回读 → 长按/X 锚定菜单 → 下一首与队尾插入 → 加入/新建歌单 → 重命名/从歌单移除/撤销；同时验证取消无修改、重开持久、当前播放不被管理动作打断。预览只验证本地模拟，真实登录/同步另行验收。
7. 普通 Player 保留 L1/R1 短按±15秒与长按临时预览合同；显式 seek 只 A 应用/B 取消、方向左/右±10秒。方向不会进入控制台其他按钮；长 Select 可达模式/歌词/定时，短 Select 松开只打开一次队列。一级页肩键切 Tab，L2/R2 仍须完整归零才再触发。
8. Name连续输入 → Start播放器 → B/Start返回，名称草稿完整且未写入业务；普通菜单Start只关闭菜单，seek中Start取消预览。L3/R3与当前集合/详情底部按钮结果一致，搜索、分类及播放器无对应批量按钮时不触发。

可复用 `thor-agent` 的专用双屏模拟器做后续窗口布局、页面流转与模拟输入调试，不直接复用其应用逻辑。参考 AVD 为 `thor_agent_dual_api36`，Android 16 / API 36 / ARM64，上屏 display 0、下屏 display 4，逻辑 density 369dpi。Thor 真机参考为 Android 13 / API 33；显示 ID 只是该环境的观测与配置，不应写死为所有设备的恒定事实。RP Duo 的系统参考是 Android 16，但不能据系统版本相同就认定它与该 AVD 的密度、输入和多屏行为一致。

模拟器可以检查双屏尺寸、焦点与恢复流程；真机仍需验证厂商多屏路由、实体手柄键码/摇杆/扳机、麦克风误触、耳机拔插、合盖、后台播放、刷新率与长期动画功耗。本文没有执行上述验收，也没有承诺帧率、电池续航或登录接口效果。

## 9. 待核对的产品决定

1. **先核对画布：** Thor 上屏 16:9、下屏 31:27，RP Duo 上屏 16:9、下屏 4:3，以及同像素缩放/按实物估算两种预览尺度是否清晰准确？该项确认后再评审上层 UI；设备范围为 Thor 主档、标准 RP Duo 次档。
2. **主题质感：** 微砂陶瓷为主方向，晶雾/钛金为同布局主题包；继续核对各包白天/夜间的材质、字重与控件层次，保持实体 CD 展示及已确认逻辑。
3. **浏览与播放：** 当前建议 A 歌曲立即播放留列表、Start 主动进入舞台；是否希望第一次播放自动进入一次舞台介绍？
4. **模型手感与首版范围：** 吹气单向驱动、直接拖动和结束吸附至相对正面的关系已确定，继续核对力度、惯性和弹簧初值；音乐源保持网易云 + 本地，云盘作为库二级入口。
5. **音频恢复：** 当前建议合盖继续播放、耳机拔出暂停、重新插入不自动播放；是否符合实际掌机使用习惯？
