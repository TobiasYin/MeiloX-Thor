## 已确认的约束

AYN Thor 为主目标：上屏 1920 × 1080，下屏 1240 × 1080。Retroid Pocket Duo 为次目标：上屏 1920 × 1080，下屏 1280 × 960。设备档与主题分离，预览只整体缩放画布。

下屏承担列表和控制，上屏展示封面、内容信息与播放歌词。首页、发现、音乐库、我的四个一级页面显示右侧导航，其余页面沉浸展示；L1/R1 仅切一级页。歌曲喜欢、专辑/歌单收藏、持久歌单成员和临时队列是独立状态。

长按或 X 唤起锚定菜单；方向选择、A 执行、B 返回。加入歌单使用同锚点、同宽二级菜单，A 即加入，返回保留焦点。3D 模型支持直接拖动、力度驱动的吹气旋转，以及结束后的近正面吸附。

## 预览的边界

浏览器中的曲目和封面是虚构示例，管理状态只保存在预览本地。预览没有接通网易云、真实麦克风或原生双屏窗口，不代表原生实现或真机验收已完成。独立预览需要联网加载其通用图标与展示运行时。

原生开发应复用项目现有账号、登录态、音乐服务、数据库及播放队列，不将预览中的内存模型当作业务实现。开发拆分、接口、实施顺序和验证记录另见本目录的开发计划。

## 原生入口

首批实现位于 `app/src/main/java/com/ljyh/mei/thor/`，启动入口是 `ThorActivity`。它使用现有 `MusicService` 和账号会话，上屏为 Activity，下屏为独立 Presentation；本地喜欢与歌单通过 Room 持久化。主题、显示档与音乐业务分别维护。

原生已经接入真实数据；浏览器预览继续作为设计基线。各页是否完成全链验收，以验证记录为准。

## 维护方式

先更新设计契约和 Token，再同步预览。重新生成独立预览时，以 `prototype.fragment.html` 为输入，并保留实际原生实现与设计提案之间的状态区分。设备支持、系统权限与服务能力必须以现有代码和设备验证为准。
