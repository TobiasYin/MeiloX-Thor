# Thor Music 设计与原生实现

本目录记录面向 **AYN Thor** 的双屏专用音乐客户端设计、原生实现和验证证据。下屏承担列表与控制，上屏展示可触摸旋转的 3D CD 封套、资料与歌词；账号、音乐服务、数据库和播放队列复用项目原有业务。

最新搜索更新让歌曲、歌手、专辑与歌单在综合前列可见，并提供五类筛选与歌手作品入口。完整应用 JVM 套件 **1,291 项通过、零跳过**，本轮相关实体 AYN Thor **8 项原生方法通过**，见[搜索歌手验证](search-artists-validation.md)。[首页发现验证](home-discovery-validation.md)的 15 项、[逐字流光](lyric-flow-atmosphere-validation.md)的 33 项及[综合真机验收](live-acceptance-validation.md)的 91 项分别保留，不相加。

## 已确认的约束

AYN Thor 为主目标：上屏 1920 × 1080，下屏 1240 × 1080。Retroid Pocket Duo 提供上屏 1920 × 1080、下屏 1280 × 960 的设备档与模拟器布局适配，尚不构成 RP Duo 真机兼容或性能承诺。设备档与主题分离；窗口使用运行时发现的实际 display 和密度，不把示例 display ID 当硬件常量。静态对照中的两屏按相同像素比例缩放，不拉伸，也不代表两块实体屏幕的物理尺寸比例。

下屏承担列表与控制，上屏展示封面、资料和歌词。上下方向／左摇杆在当前列表或显式选项 scope 内移动，不进入右侧 Tab、页头、页脚或迷你播放条；左右在首页、歌手详情与非编辑搜索页直接切分类，在其他封闭列表不越界。新入列表（含队列）及每次新搜索结果都选首项，返回已有列表恢复稳定 key 与滚动；队列和歌词的「定位当前」唯一入口为长 Select 页面操作菜单，不再保留独立底部按钮。四个一级页仍以 L1/R1 切 Tab，其他一级页 B 先回首页，首页首次 B 提示、两秒内第二次独立 B 才退出；其他实际输入/触摸/导航/后台清退出计时，重复 DOWN 不确认。

上屏封面、标题、歌词行及滚动容器不参与手柄／键盘焦点，不显示导航选中框。封面触摸拖动与转面、歌词手动浏览和单击行播放继续保留；歌词拖动及自动跟随不会触发 seek，拖动和惯性全部停止 15 秒后恢复当前行。

短 Select 在松开时切换队列，长 Select 500ms 打开「页面操作」，覆盖分类、搜索、刷新、导入、新建、定位当前，以及 Player 模式/歌词/定时/进度等真实可用按钮。X/触摸长按只打开条目菜单；上下/A/B 的菜单与父子层规则保持。除定位当前统一收至页面操作菜单外，其他触摸 UI 保留，按钮不必靠方向越区抵达。

Player 仅播放/暂停主焦点，A/Y 控制；正常 Player 短按 L1/R1 后退／前进 15 秒，长按松开提交进度。显式 seek 仅 Apply 主焦点，A 应用/B 取消、方向左/右±10秒；其中再长按肩键仍可松开提交，进入 seek 不打断肩键 hold。导航和菜单切 scope 则清理持有输入。Appearance、Controls、Timer 只在选项区 Spatial 导航；Name 仅明确编辑区域，Start 可挂起同账号草稿后恢复。L2/R2 保留归零锁存，L3/R3 仅有真实批量动作时生效。喜欢/收藏、持久歌单和临时队列仍为独立状态；3D 模型触摸、气流与收尾归正不改变选曲。

音乐播放时停止麦克风吹气采集，并在模型层拒绝气流输入；已有吹气旋转就近归位，封面改为轻柔呼吸。暂停、服务连接与前台条件满足后才按原偏好恢复，播放中不执行校准。触摸拖动仍可接管模型；减少动态和隐藏会停止装饰帧。本轮实体机已验证实际 MIC session 随播放停止、暂停恢复两轮；吹气操作由用户反馈正常并要求不再重复验收，未加入自动通过数。

明确不可播放的在线歌曲保留浏览和管理能力，播放与队列插入先过滤已知受限项。运行时未知失败不直接永久判为版权问题；既有同曲恢复耗尽后，在有限候选和时限内预检，只有找到可用候选才切换一次。“音源不可用时尝试下一首”默认开启，既有明确关闭值保留。关闭时、全部候选失败或预算耗尽时会暂停并集中提示，不能保证无可用音源时继续播放。详见最新恢复记录。

## 预览的边界

浏览器中的曲目和封面是虚构示例，管理状态只保存在预览本地。预览没有接通网易云、真实麦克风或原生双屏窗口，不代表原生实现或真机验收已完成。独立预览需要联网加载其通用图标与展示运行时。

原生实现复用项目现有账号、登录态、音乐服务、数据库及播放队列，预览中的内存模型仅用于设计示例。静态截图、模拟器回归和实体设备证据分别记录，不能彼此替代，也不表示所有规划页面和在线服务器交互都已完成验收。

## 原生入口

主要实现位于 `app/src/main/java/com/ljyh/mei/thor/`，启动入口是 `ThorActivity`。它使用现有 `MusicService` 和账号会话，上屏为 Activity，下屏为独立 Presentation；没有可用副屏时保留下屏操作的单屏回退。本地喜欢与歌单通过 Room 持久化。主题、显示档与音乐业务分别维护。

登录、账号与绑定、音频设置和十段均衡器已进入同一 ThorActivity 的原生导航，不再为这些入口打开旧 MainActivity；输入与主题沿用 Thor 契约，业务仍复用现有仓库、DataStore 和 PlayerConnection。通知“上屏歌词”进入 Thor 播放页。网页和验证码使用下屏窗口；测试覆盖承载与输入路由，没有以合成网页结果代替服务器真实挑战成功。USB 独占／原样输出效果没有模拟器硬件结论，旧版 Android PiP 未因此迁入 Thor。

“关于”等未迁移路径继续保留旧兼容机制，不能将本轮称作原版所有页面已完全重写。各入口的实际覆盖范围及账号敏感操作的验收边界见 [内嵌设置记录](embedded-settings-validation.md)。

## 维护方式

先更新设计契约和 Token，再同步预览。重新生成独立预览时，以 `prototype.fragment.html` 为输入，并保留实际原生实现与设计提案之间的状态区分。设备支持、系统权限与服务能力必须以现有代码和设备验证为准。
