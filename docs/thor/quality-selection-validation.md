# 播放音质选择与每曲回退

播放页新增音质入口，显示当前实际档位；触摸或长 Select →“播放音质”进入同一 ThorActivity 下屏的选择页，上屏继续保留正在播放的封面、歌词与背景。方向键只在八个音质选项内上下移动，初焦点位于已设定的默认档，A 应用后返回，B 取消返回。播放器主焦点仍只有播放／暂停，方向不进入音质按钮、标题或页脚。

## 默认与实际分开

用户主动选择音质会更新既有 `MusicQualityKey` 全局默认，并沿原 `PlayerConnection.changeQuality` 刷新当前歌曲。没有当前歌曲时也可以先设默认；播放器未连接或正在编辑进度时入口明确禁用。

当前曲目拿不到目标档位时，只改变该曲的实际音源，不回写默认。选择页显示“默认 Hi-Res · 当前 无损”，默认勾选和当前标记独立；下一首仍从用户的 Hi-Res 目标开始请求。本地文件显示“本地”，不虚构云音质。主动切换继续保留队列、条目身份、播放位置和播放／暂停意图。

## 最高可用完整音源

此前请求高档音质时，只要服务器返回低档完整 URL 就会立即采用，可能错过仍可用的中间档位。现在先保留低档候选，再按现有音质菜单由所选档向下检查，选出最高可用的受支持完整源：

`杜比全景声 → 超清母带 → 沉浸环绕声 → 高清环绕声 → Hi-Res → 无损 → 极高 → 标准`

例如请求 Dolby 得到 standard，但 lossless 实际可用，则采用 lossless；全局仍为 Dolby。请求较低档时只探测该档及其下方档位。此顺序沿用原应用的选项层级，不代表不同编码的声学优劣保证。试听片段不作为完整音源，网络及外层业务错误不会被当作音质缺失。

URL 缓存只按实际档位存放；已完成的“目标→实际”搜索结论单独缓存，避免每次数据读取重跑全部请求。后续探测已取得更高可用源时可更新实际选择。源失效、账号变化、解码拒绝和用户主动重选会按对应范围清理结论；不污染其他歌曲或全局偏好。
