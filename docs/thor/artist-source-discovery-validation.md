# 歌手完整音源判定与首页／发现分工

本轮针对“林俊杰页面的歌曲播放失败”和“发现页与首页歌单重复”两项问题。已在实体 Thor 上复现并核对播放失败的直接原因，修复完成构建及完整 JVM 验证；**修复后的原生与在线验收仍待真机恢复连接，尚未宣称通过**。

## 林俊杰页的实际原因

独立 subagent 在当前真实会话下，对林俊杰（歌手 ID `3684`）热门列表前三首 `108485`、`2041026502`、`108914` 对比了歌手列表 metadata、标准歌曲详情及音源响应，并选取其中一首实际试播。歌曲 ID、时长、专辑和艺人对应一致；原列表与歌曲详情均为 `Unknown`，没有提前提供明确的不可播放标记。

三首音源接口均返回外层与单条 `code=200`，也包含 URL，但 `freeTrialInfo` 存在，实际是试听片段。完整音源解析按既有策略拒绝三首试听片段，均触发 `SourceNotFoundException`；实际播放器抽测的一首没有推进，报错代码为 `2000`。列表却仍允许用户按 A 播放，造成连续失败的体验。陈奕迅的另三首采样也有相同响应；相同歌手链路中的完整音源对照曲 `35403523` 和另一歌手的完整音源，均真实生成新队列条目并推进 Media3 进度。

这证明了采样歌曲的“仅有试听源但列表未标明”问题，不说明所有林俊杰歌曲均不可播放，也不能据此推断账号会员类型或确定版权归属。前轮歌手验收覆盖目录、导航与作品分页，实际播放正例使用另一个搜索／每日推荐曲目，没有覆盖这批试听歌曲；这一覆盖缺口已补充为独立真机测试。

[修复前的脱敏诊断](artist-source-discovery-evidence/diagnosis-before-fix.json) 保留歌曲 ID、必要 metadata、返回码、试听标记和新条目实际推进结果，不含 URL、Cookie、账号 ID 或私人歌单。正例中来自先前失败的残留 notice 已移除，避免被当作正例的新错误。

## 完整音源提示

歌手热门歌曲与全部歌曲读取后，对权限仍为 `Unknown` 的在线歌曲按最多 50 个 ID 批量检查，复用现有音质回退和完整音源规则，按 Long ID 匹配响应：

- 任一受支持音质取得完整音源，标为可播放。
- 所有尝试音质都明确返回有效试听片段，标为不可播放，原因是“当前账号仅可试听”。
- 缺失 ID／URL、网络或业务错误、未知格式继续保留 `Unknown`，不把失败猜成版权限制。
- 本地音乐、Podcast 和已有明确权限状态保持原策略；不持久化新 URL 或权限判定。账号检查覆盖每批请求前后，取消与会话变化继续传播。

默认 `exhigh` 下，一页 40／50 首最多增加两次音源元数据请求；已经获得完整音源的歌曲不再探测较低音质。列表顺序、歌曲 identity、分页和账号隔离保持。已知受限项仍可浏览和管理，按 A 会在替换当前队列之前拦截；播放中遇到未知不可用源的既有有界跳过逻辑继续保留。

## 首页与发现的分工

此前首页“歌单”和发现都调用高品质歌单列表，确实重复。对照原版 Home 推荐内容与 FindMusic 分类浏览的职责，现为：

| 页面 | 内容与接口 | 操作 |
| --- | --- | --- |
| 首页 → 歌单 | `/api/personalized/playlist` 推荐歌单 | 查看、打开、刷新；不虚构分类或游标 |
| 发现 | `/api/playlist/highquality/list` 分类高品质歌单 | 语种／风格／场景分类，真实 lasttime 游标续页 |
| 首页 → 推荐／榜单／歌手 | 原首页推荐、官方排行榜及歌手目录 | 保留现有内容、歌手地区与类型、作品页及搜索 |

发现保留紧凑 56dp 标题行和 48dp 分类／搜索热区。手柄方向只移动列表，分类通过触摸或长 Select 的页面操作菜单打开；末尾 A 加载更多后交接到第一条新增内容。发现分类不再清空首页推荐数据与焦点；主列表使用独立 `root:Discover:playlists` 记忆，分类菜单的光标不会覆盖原位置，B 取消后恢复原行和视口。两种接口可能返回重叠歌单，这不代表页面职责相同，也没有通过过滤 ID 人为制造差异。
