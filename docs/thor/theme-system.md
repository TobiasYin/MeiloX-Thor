# Thor Music 主题系统契约 v1

日期：2026-10-30，实施状态更新至 2026-10-31。本文保留已确认的主题设计契约，具体值见 [设计 Token 数据](theme-tokens.json)。内置三套材质、完整白天／夜间、系统跟随、共享组件与双屏切换已按契约实现，结果见 [视觉还原记录](design-parity.md)。文中可安装第三方主题包、包格式验证与回退仍为后续扩展契约；原生实施建议中的“拟”描述保留作设计来源，不表示上述内置系统尚未落地。

页面与手柄基线见 [完整设计稿](design.md)，主题行为以本文契约为准。

## 1. 两个正交维度

**主题包决定品牌与材质，day/night 决定全局明暗。** 用户选择分别保存为 `themeId` 与 `modePolicy`，后者为 `system | day | night`。选择新主题包不会重置明暗偏好；系统跟随时，系统模式变化同时作用于所有可见页面、双屏、菜单与弹窗。

每个主题包必须同时提供完整白天和夜间版本。播放器也服从同一全局模式，取消默认强制深色播放器；白天播放器使用浅色承载面、深色歌词，夜间使用深色承载面、浅色歌词。专辑封面保留原图颜色，不要求图像本身变白或变黑。没有页面级明暗覆写，也不允许只交付深色播放页来冒充双模式主题。

布局、路由、焦点路径、播放队列、控件行为与设备档独立于主题。切换主题不移动焦点、不重置滚动、不改队列、不重新开始播放。两屏在一次主题事务中更新，避免上屏白天、下屏夜间的中间状态。

## 2. 三个主题包

主方向为**微砂陶瓷 Ceramic**，以 Soft UI Evolution 的微砂底、窄高光、轻接触阴影建立质感，播放主按钮使用精细音响控件的表面与边缘处理。另有完整可切换的晶雾 Glass、钛金 Titanium；三包保持相同布局、焦点、尺寸与功能，均提供完整 day/night。这是已确定的设计方向，不表示原生应用已经实现主题切换。

| 主题 / 稳定 ID | 白天质感 | 夜间质感 | 保持一致的部分 |
|---|---|---|---|
| 微砂陶瓷 / `ceramic` | 暖白微砂釉面、窄高光、柔和接触阴影 | 石墨微砂釉面、克制边缘反光 | 明确层次、柔圆转角、精密焦点边框 |
| 晶雾 / `glass` | 高不透明浅玻璃、局部光泽与细高光 | 烟色高不透明玻璃、稳定承载层 | 正文下有稳实底层；反光不盖文字 |
| 钛金 / `titanium` | 缎面钛银、琥珀/铜强调、局部精细倒角 | 深阳极铝、低亮金属刻度与铜色强调 | 音频设备的紧凑节奏，不额外增加装饰仪表 |

材质由底色、微纹理、边缘光、阴影与状态反馈共同构成，不靠每页另画一套控件。上屏 CD 盒可更明显地表达实体材质，下屏保持文字清晰和操作秩序。纹理只在大面积表面低强度出现，不穿过歌词、列表正文或焦点描边。

## 3. Token 分层

基础层提供颜色、尺寸、字体、时长等受控值；语义层表达用途；组件层引用语义，不在页面中直接硬编码。组件状态由应用状态机提供，主题只定义状态外观。

| 层 | 必需契约 |
|---|---|
| Semantic palette | `canvas`、`surface`、`surfaceRaised`、`surfaceOverlay`、`textPrimary`、`textSecondary`、`textDisabled`、`accent`、`onAccent`、`border`、`focusRing`、`scrim`、`success`、`warning`、`error` |
| Material | `finish`、`texture`、`textureOpacity`、`surfaceOpacity`、`blur`、`edgeHighlight`、`contactShadow`；提供不透明降级表面 |
| Typography | 中文/英文/数字字体栈、标题/正文/辅助/歌词字号、字重与行高；数字使用等宽数字特性，中文保留系统字体兜底 |
| Spacing / shape | 4/8dp 基础节奏、内部间距、控件/面板/菜单圆角、描边粗细；值在组件批准范围内 |
| Light / shadow | 接触阴影、抬升阴影、高光强度与方向；阴影不能成为唯一边界 |
| Motion | 按下/选中/主题切换、盒体浮动、环境流动、吹气曲线、拖动反馈、惯性与展示角吸附参数；不定义播放与焦点逻辑 |
| State appearance | default、focused、pressed、selected、playing、liked、collected、disabled、loading、error 的颜色、描边、填充与图标处理 |

`selected`、`focused`、`playing` 允许并存，不能互相覆盖。组合状态按角色叠加：选中填充、正在播放图标、最外侧焦点环；按下反馈改变高光、填充与接触阴影，不改变布局边界，也不整体压低文字和图标亮度。禁用项保留可读原因，不能仅降低透明度到看不见。

菜单/二级菜单当前活动项必须有选中填充与对比描边，业务 `selected` 和导航 `focused` 独立、可并存。鼠标点击模拟按键或浏览器隐藏 `:focus-visible` 时，显式活动态仍应可见；主题不能把它退化为仅 DOM 焦点环。打开初始高亮、↑/↓ 循环与滚动跟随、A 执行、A/→ 进子层、B/← 返回和背景独占由交互层控制，三主题两模式保持相同语义。

歌曲 `liked` 与专辑/歌单 `collected` 是不同业务状态，主题只提供图标/填充/标签外观，不能决定是否持久或同步。状态可与播放、焦点并存；使用空心/实心或清晰标签，不只改变颜色。长按/X/更多菜单、加入歌单二级菜单、轻量命名层与撤销反馈复用 Overlay/ActionButton；对象、同锚点同宽、边界钳制、接管优先级与即时加入/取消由交互层决定，主题不得改成长按模型抢占拖动。子层过渡初值约 170ms、水平且可中断，不延迟输入；减少动态时直接替换，不变成居中对话框或两列布局。

主题可调整细节质感，不能自行更改按钮最小热区、列表行高、标题结构、播放器控制组位置或底部操作分区。排布尺寸由组件契约与设备档确定；字体和间距的变化不得突破这组边界。

上屏歌词使用共享 `foundation.lyricLayout` token组：`rowGap=16`、`rowVerticalInset=8`（上下各8）、`auxiliaryTopGap=8`、`auxiliaryGap=6`、`lineHeightEm=1.5`。间距为设计逻辑单位，原生映射到实际窗口；当前行24、相邻行22、译文14，每行热区至少48dp。较小的主/邻字号差减少切行时的换行差异，主行仍以字重、语义色与逐字进度强调。歌词上下留白各占窗口高度5%，标题间距12dp；顶部24dp、底部36dp使用真实alpha渐隐，跟随锚点为视口的23%，首末行也能进入清晰区域。以上值分别由 `viewportVerticalInsetFraction`、`titleGap`、`edgeFadeTop`、`edgeFadeBottom`、`followAnchorFraction` 统一提供。三主题与日夜采用同一排版基线；拖动浏览、全部滚动停止15秒恢复跟随、单击复核entry后seek并play属于交互层，不能由主题改变，也不作为界面常驻解释文案。

## 4. 组件契约

| 组件 | 可由主题决定 | 必须由功能/布局决定 |
|---|---|---|
| AppSurface | 页面/抬升面/覆盖面材质与环境层 | 页面层级、屏幕角色、安全边距 |
| NavRail | 背景、选中态、焦点和图标样式 | 仅四个一级页显示、顺序与肩键规则 |
| CompactHeader | 字体、分隔线、数量标签颜色 | 返回、标题/分类、右侧数量的单行关系 |
| MusicRow | 表面、封面边缘、正文与状态样式 | 数据字段、列表密度、点击与队列行为 |
| PlayerDeck | 舞台明暗、CD 材质、环境光、歌词色 | 独立控制台分组、真实下一首、播放状态 |
| ProgressTrack | 轨道/缓冲/进度/焦点/预览刻度样式 | 时间、seek 编辑、A 提交/B 取消 |
| ActionButton | 主/次/危险按钮材质与状态外观 | 文案、权限、动作、至少 48dp 热区 |
| Overlay | 菜单/弹窗承载面、遮罩、阴影 | 打开/关闭、模态消费、焦点返回与确认 |

歌词、输入候选、扫描进度、错误和离线空态也必须使用上述统一语义角色，不能变成主题遗漏区。页面不展示主题契约、分工或状态机解释；只显示真实内容、必要状态与操作标签。

## 5. 明暗、封面与可达性

正文和辅助正文在两模式下均以至少 4.5:1 为目标；承担意义的图标、边界、选中/焦点指示至少 3:1。焦点同时使用轮廓、位置标与填充差异，不能只靠色相。禁用状态仍需辨认文字，不能误用对比度较低的装饰色承担操作信息。

封面提色只进入独立环境层，如背景光晕、盒体反射或弱阴影色。正文、歌词、焦点、按钮标签与错误色始终来自当前主题语义色，不被封面颜色覆写。环境层有强度上限和隔离承载面；在最亮、最暗、单色与高饱和封面上检查实际合成结果。

`reduceMotion` 关闭连续旋转、惯性、弹簧过渡、盒体浮动、视差、背景流动与装饰过渡，手动操作直接切换至相对正面的静态展示角，保留必要的播放状态和歌词内容更新；不能冻结歌词时间轴。`reduceTransparency` 使用不透明承载面与边界替代透射/模糊，保留 CD 盒的实体形状。两项独立组合，并覆盖菜单、加载、错误和主题切换。

模型的共同 motion 契约为：吹气驱动阶段绕 Y 轴固定正方向累计旋转，两面保持同一封面。标准化输入经约 80ms attack 平滑为 `s ∈ [0,1]`，目标角速度 `600 × s^1.45 °/s`，加速约 200ms；停吹先以约 420ms 时间常数惯性减速，再根据约 180ms 余速投影选择最近的正/背面展示角，用临界阻尼弹簧柔和吸附。最终合成 `rotateY = -16° + k × 180°`；基础 `preferences.angle` 仍可调，局部吸附目标扣除基础角，确保最终是 16° 轻透视。弹簧初值为自然频率 8rad/s、质量归一化阻尼 16，允许收尾小幅回摆，不生硬跳角或停在侧面。这些均为可调设计初值。

直接拖动具有最高接管优先级：水平绕 Y 轴双向跟手，垂直小幅俯仰且限幅；按下中断吹气/惯性/吸附，释放估计速度后继续同一惯性与吸附。拿起反馈只改变轻微抬升/缩放与接触阴影，不改变热区或布局。主题不能把旋转/拖拽绑定到选中、确认或播放，也不能用材质切换改变这套输入关系；未来右摇杆可等效调整。预览以原生语义 button 提供左右/Enter 等效操作，并使用画布外力度滑杆与有限脉冲，不读取麦克风；减少动态时直接切到相对正面。原生校准、噪声、输入手感与功耗仍待验证。

### 播放环境层（已实现，2026-10-31）

播放背景是独立的环境层，沿用三套材质与全局日夜模式；它不重定义正文、按钮和焦点颜色。当前原生配置由 `ThorBackdropProfile` 集中解析，封面数据由 `ThorArtworkPalette` 提供，`ThorPlaybackBackdrop` 负责绘制与过渡。后续主题可扩展这层外观参数，布局、取色与播放逻辑继续独立。

| 背景模式 | 环境外观 | 动态行为 |
|---|---|---|
| 封面流光（默认） | 提取封面三组代表色，融合柔焦色场、宽光带、边缘收光和微纹理 | 播放时缓慢流动，暂停缓停；换封面约 1100ms 平滑过渡 |
| 柔焦渐层 | 保留封面配色，使用更轻的静态渐层 | 无持续动画时钟 |
| 纯净 | 使用当前材质的基础舞台底色 | 无装饰动画；强度控件禁用但保留原选择 |

`backgroundMode` 与 `backgroundIntensity` 独立于材质、明暗和账号保存，默认 `ArtworkFlow / Medium`，低／中／高只改变视觉强度，不加快流动。下屏“我的 → 主题与外观”修改时，上屏实时预览；退出外观页即结束预览。日间采用浅柔焦色、夜间采用低亮色，歌词区域逐步减弱背景色，保留稳定的正文对比度。

减少动态关闭持续流动，并立即应用颜色／模式切换；减少透明降低环境色权重并移除光带高光和微纹理。不可见或生命周期停止时停止装饰时钟；再次可见从原相位继续，不累计隐藏时间。彩色封面、灰度／缺失／无效封面都经过同一安全调色路径。原生实现与模拟器证据见 [播放环境层验证](playback-atmosphere-validation.md)。

## 6. Schema 与最小示例

当前设计 Token 数据是一个便于统一校核的三主题集合，结构为 `schemaVersion`、`foundation`、`themes.<id>.shape/lighting/appearances.day/night`。预览只消费设计值，不实现第三方主题包加载。数据中的 `ink/muted/line/focus` 分别对应上述语义契约的 `textPrimary/textSecondary/border/focusRing`；`selectedInk` 单独保证浅色与深色选中项文字的对比度。当前具体色值以该数据文件为准。

未来可安装主题包拟使用以下单包封装，必需字段为 `schemaVersion`、稳定 `themeId`、包 `revision`、兼容的 `themeApi`、基线 `extends`、名称，以及 `modes.day/night`。其余材质/字体/间距/形状/光影/动效/组件覆盖值可继承内置基线；一个模式不能继承另一个模式。资产以包内标识引用，主题只包含数据，不携带路由、脚本或布局。

以下为未来单包格式的最小示例，展示同一组陶瓷设计值如何封装；它不是当前预览集合文件的直接替代：

## 7. 未来 Compose 映射与迁移边界

拟采用不可变的 `ResolvedTheme` 统一合并当前包、明暗模式与可达性选项，再通过 CompositionLocal 提供 palette/material/component tokens。可对应的基础语义映射到 MaterialTheme，其余由组件读取；MaterialTheme 本身不足以表达盒体、舞台和材质。此处是实现建议，没有新增 Kotlin 类型或资源。

DeviceProfile 独立负责 Thor/RP Duo 的画布、逻辑单位、控件边界与紧凑程度，不放进主题 Schema。主题改变皮肤，不改变设备档；Duo 的实际 density 仍待设备读取，不能从主题推断。

迁移先抽取现有硬编码颜色和组件状态，建立内置双模式基线，再接入材质包与数据验证。全局模式应用到所有页面，播放器不再强制独立深色。保留已核对的布局、手柄、返回、队列和编辑语义；此次不顺带重排播放器或列表。后续实现中应单独验证主题变更造成的重组与渲染开销。

## 8. 全主题、全页面验证矩阵

每个拟发布主题包必须检查 day/night 两模式、Thor/RP Duo 两设备档，以及普通/减少动态/减少透明/两项都开的组合。系统跟随还要在双屏可见、模态打开、正在播放时测试切换。以下每组均检查适用的正常、聚焦、按下、选中、禁用、加载、空、失败和离线状态，以及长文本/大字号。

| 页面覆盖 | 重点检查 |
|---|---|
| P01 引导、P02 连接 | 校准、输入/权限、连接状态、错误恢复可读 |
| P03 首页、P04 发现、P05 音乐库、P18 我的 | 一级侧栏、数据分组、封面环境光、未连接/离线 |
| P06 专辑、P07 歌曲、P08 详情、P09 歌手 | 单行页头、数量、焦点/播放并存、正文与封面隔离 |
| P10 搜索 | 字符面板、候选、输入焦点、空结果/失败 |
